# Full renderer

The renderer owns Three.js presentation of the shared `RegionDefinition`, `ActorSnapshot`, `CombatSnapshot`, `AssetManifestEntry`, and `EnvironmentRecipeDefinition`. Simulation remains the authority for movement, collision decisions, contact timing, camera-independent world state, and campaign progression.

## Public API

```ts
const renderer = new GameRenderer({ canvas, onProgress, lodPolicy? });
await renderer.loadRegion(region, assetManifestEntries, environmentRecipeDefinition);
await renderer.preloadActorVariant('orun', 'actor-orun-crowned-beast', manifest);
renderer.sync(combat.actors, combat, deltaSeconds, previousCombat, renderAlpha); // every RAF
presentation.update(combat.worldClock);
renderer.render(); // draw only after socket-bound presentation has sampled the pose
renderer.syncWorldFacts(campaignFacts);
renderer.getInputBasis();
renderer.resolveSocket(actorId, socketName);
renderer.capture();
renderer.dispose();
```

loadRegion checks the composed recipe ID, procedural layers, exact placement and ground-surface IDs, and recipe prop membership before scene commit. The region-specific environment is a code-authored composed recipe, not a guessed GLB URL. Static placements use their exact prop manifest IDs and authored transforms. Actor RegionEntity.id joins its unique runtime ActorSnapshot.id; the explicit entity.assetId resolves the native character manifest, while entity.actorId and snapshot.archetypeId identify the canonical actor definition. Multiple instance IDs may share one actor manifest and receive independent SkeletonUtils clones. A load stages assets before replacing the active scene. A newer load supersedes an older staged load; stale asset completions release their leases and cannot commit over the newer scene. Failed or superseded staging preserves the last committed region.

`preloadActorVariant` requires exact character `actorId`/`variantOf` correspondence. `ActorSnapshot.renderVariantId` is an exact asset ID; missing selected variants hide the base rig and are reported in capture data instead of falling back to the wrong form. Variant completion after a region change is released as stale.

mountCompanionPreview(host, companionId, assets, { idleActionId, loader? }) loads the exact actor manifest for that companion and returns a CompanionPreviewHandle with update(dt), actionTime, and idempotent dispose(). The caller passes the canonical actor-specific ActionId (for companion IDs, the existing catalog maps id:idle) and advances update from the existing application RAF only while the preview is active; the renderer owns no second loop. Camera framing is fitted from the loaded native bounds with a directional key and fill light. A detached/replaced host during load releases the instance and rejects as stale; a missing idle mapping fails rather than falling back.

## Native asset bytes and ownership

Every native GLB load requires a 64-character manifest `outputHash`. The loader fetches the exact runtime bytes, computes SHA-256, compares the digest before parse, checks GLB 2.0 framing, and rejects buffer/image URIs that point outside the self-contained GLB (embedded `data:` resources are allowed). Missing hashes, hash mismatches, external dependencies, malformed payloads, unskinned character models, and missing required native clips fail visibly. Only the development loader may create in-memory motion for a blocked candidate GLB with zero embedded clips and an explicit profile; it never fills a required native action mapping.

Cache identity is the asset ID plus lowercased immutable output digest and serialized playtest profile; runtimeUrl is a fetch location, not revision identity. Same-digest aliases and same-revision overlapping loads share one in-flight fetch/template. Instances hold leases on shared template geometry/material/texture resources; cache capacity evicts only unleased templates, and retired digests are disposed after their last lease. Template cleanup disposes unique geometries, materials, and referenced textures. Static prop batches own cloned instancing geometry/materials while retaining the source template lease until batch disposal.

For blocked local-playtest candidates only, `CandidateGeometrySimplifier` preserves the previous index-only reduction for skinned/morphing meshes and compacts static props after error-bounded, per-material-group simplification. Large static meshes target at most 8,000 triangles at 1% error; the error bound may retain more triangles. Compaction preserves normalized integer rows, interleaved attributes, material groups and source-buffer ownership. Native GLB bytes and hashes never change. Each instancing batch owns distinct GPU attribute identities while sharing immutable CPU storage and retaining its template lease.

The manifest's canonical action mapping is `actionToClipMapping` (`ActionId` to exact provider clip name); `requiredActionIds` must map to clips present in the native GLB. Finite clips sample `ActorSnapshot.normalizedTime`. Looping clips integrate deltas of the authoritative actor clock, using a velocity-derived rate for locomotion; duplicate clocks do not advance phase, a zero locomotion rate holds it, and a clock rewind reseeds it. Walk↔run transfers normalized gait phase between different clip durations and cross-fades. Render-frame delta advances fade weights, not gameplay action time. Aliased action IDs retain their own manifest/root-motion identity even when they share one native `AnimationClip`. Repeated finite actions resample their new normalized progress and retain the endpoint when complete. Missing native action clips throw `AnimationBindingError` rather than selecting an arbitrary clip. `playtestAnimation` remains a separate development-only profile; its generated clips do not alter canonical mappings or required-action evidence.

Per-action root motion must have verified metadata. For `native-root-motion` and `authored-curve`, the controller requires `rootNodeName` and finite curve samples, and captures the canonical root bind before playback. By default it restores the full bind translation after each animation sample. Explicit `preserveVerticalMotion: true` removes horizontal travel while preserving the native vertical crouch and bob; it does not transfer root travel into simulation state. "Vertical" is the actor-space up axis expressed in the root node's parent frame, captured from the bind hierarchy: parent-local Y for Aren, local Z for Yara's Z-up Tripo/Mixamo armature (whose kneeling Sap Lance previously floated ~0.5 m because its drop was reset as if horizontal). Axis-aligned rigs keep bit-identical horizontal resets. Simulation actor position remains the only world-displacement authority. Missing or unverified root-motion policy fails closed when that action is played. `in-place` clips also require verified per-action declaration. Playtest-generated clips contain only quaternion tracks and receive runtime-only in-place policy; this is not release evidence. Authored contact records are exposed only for the currently active action; no contact timing or gameplay event is inferred from render delta.
Locomotion cadence reads the clip's authored ground speed in actor X/Z: `AnimationController` caches `authoredPlanarSpeed` per verified `native-root-motion` walk/run/strafe action when it captures the root bindings, and `ActorAnimationDriver` (`nativeLocomotionPlaybackRate`) plays the loop at actor speed divided by that cached value. The cache carries the Hips curve displacement through the root node's bind parent-to-actor matrix (rotation and scale) and then multiplies by the manifest `coordinateTransform.scale`. An earlier version read the displacement in the parent's local X/Z, which is only the actor's ground plane when the parent adds no rotation; Vesper's native root parent rotates its local −Y onto actor +X, so the speed (and with it the playback rate) was taken from the wrong axes. A permanent regression drives the actual controller and driver with a rotated and scaled root parent: before the fix the observed phase stayed at 0 where 0.5 is expected, after it reaches 0.5 and the vertical bob and root compensation are correct. A provisional smoke through the real `GLTFLoader` and `AnimationController` on the exported Vesper and Sakda candidates observed that both scene wrappers map native +X to runtime +Z, that the planted walk toes travel along −Z, and that the cache returns 0 for Sakda walk/run and Vesper walk and about 4e−7 m/s for Vesper run (so the bob causes no unintended playback scaling); no manifest heading change was needed. These observations were made on assets that were still being regenerated, so the final integrated geometry and browser runs are still pending.
The local Greenwake development playtest binds the user-supplied Aren movement clips and donated Idle/Cheer/Defeat to their semantic actions. Its 65-joint skin and measured Hips curves support local action routing, root-motion compensation and locomotion cadence. The candidate remains evidence-blocked, is not exported to production manifests, and leaves unrelated authored actions unbound.

### Sockets and the `cast` head binding

Explicit manifest socket names resolve against the native scene. For a blocked character lacking an explicit `cast` socket, `NativeAssetLoader` also resolves `playtestAnimation.headBoneName`, allowing GLTFLoader's sanitized form of that name, and accepts only the actual native Bone. ## Scene and camera behavior

Ground and water vertices use absolute world coordinates from authored `GroundSurfaceDefinition.points`; `elevation` is not added again. Rendering uses the same first-point polygon fan triangles as physics `groundHeightAt`, with winding corrected for visible upward faces. No decorative height is introduced apart from authored geometry. Restored/partial facts are applied through recipe restoration keys and authored `visibleWhen` changes; the renderer does not infer progression. Every authored `REGIONS` entry now publishes partial/restored boolean facts; `RegionEnvironment.syncWorldFacts` retints authored surface materials from those booleans (restored → 10% `PARTIAL_RESTORATION_TINT`, partial → 20%, neither → base color). The browser fixture verifies the partial/restored/neutral tint transition against the existing real-renderer code path.

Greenwake's ground is a visual terrain, independent of the walk-mesh (`src/world/GroundTerrain.ts`, `RegionGround.ts`). A deterministic mesh covers `region.bounds` plus a 16 m margin: a 1 m grid whose cells near walkable boundaries, embankments and the creek gully (about 1,730 of them) are split into 0.25 m quads, with neighbouring coarse cells re-triangulated through the fine boundary vertices so the mesh has no T-junction cracks (about 61 k vertices / 122 k triangles in total; 55 k / 109 k before the ridge and creek). Every terrain-backed walkable is part of the mesh and no longer drawn as a plate: its height is exactly 0 on y = 0 surfaces and exactly the authored plane on raised ones (root ramp, earthen ridge top, grove gateway ramp), within 2 cm on the rendered mesh; `greenwake-canopy-floor` is never drawn if present. The one exception is the rope-bridge deck (material `greenwake-bridge-deck`): the `prop-greenwake-rope-bridge` model is its only visual and the gully runs beneath it. Where a raised footprint overlaps a flat one the terrain follows the raised plane when the ramp's y = 0 foot lies inside the flat surface (gateway inside the first forest corridor, root ramp inside the forest floor) and stays flat otherwise (the ramp's east flank over the boar thicket, which is never touched); at such ownership changes the terrain necessarily steps within one 0.25 m cell. A raised walkable keeps its edge height across a 0.36 m shoulder (one fine-cell diagonal, so no triangle can mix a walkable point with a vertex that has left its height), then an embankment falls into the surrounding relief over a noise-varied run (rise/run 1.0–1.6 with rocky relief added mid-face, never a wall); footprints blend with a d⁻⁴ weighting so faces stay continuous across concave corners. Just outside flat walkables a natural berm starts 0.36 m out and rises +0.35…+0.9 m (noise-varied) within 0.4–2.4 m, then falls back into open-ground mounds (up to +1.2 m) and dips (down to −0.3 m) that fade in from 3 m; edges facing away from the fixed camera get the tall, steep bank, camera-facing edges stay at ≈0.35 m so a bank never hides Aren, and the outward normal blends every edge within 1 m of the nearest one so the berm stays continuous across concave corners. The creek gully (`GreenwakeCreekShape.ts`) is carved between the ridge (x ≤ 13.5) and the gateway ramp (x ≥ 17): a gently meandering centreline around x ≈ 15.25 from a head near z ≈ 10 (north of the thicket) to a tail that shallows and fades into the forest past z ≈ 30, a bed about −1.3 m deep and concave rocky/muddy banks that reach the 2 m rim exactly at the walkable edges (steep, up to ≈ 3.5 rise/run at the bridge reach, where the gap is only 3.5 m). The carve fades to nothing at any walkable footprint, so it never lowers terrain inside one; under the bridge the terrain is ≤ −0.9 m at the midpoint and ≥ 0.3 m below the deck everywhere. Terrain is presentation only; walkability stays with the simulation. `GroundWater.ts` draws the creek as one transparent, shadowless strip (624 vertices, one draw call, `ShaderMaterial` with fog) lying 0.2 m over the bed (−1.1 m under the bridge) and clamped under the ground and faded at both ends: scrolling two-octave procedural ripple normals flowing downstream (driven by `RegionEnvironment.update`'s world clock), depth tint, bank foam, fresnel sky mix and a sun glint; the terrain mesh itself hides the strip wherever a bank rises above the water. `GroundMaterial` shades the terrain with one `MeshStandardMaterial` (lights, shadows, fog kept) patched to blend four CC0 Poly Haven 1k layers from `asset-source/textures/greenwake/<id>/` (forest litter `leaves_forest_ground`, moss `forest_leaves_02`, compacted trail earth `stony_dirt_path`, gravel shoulder `grass_path_2`; each folder has `provenance.json`) using a baked splat mask (`GroundMask.ts`, 0.25 m/texel: trail core from `navigation.ribbons` distance — now including the ramp, ridge top and gateway segments, but not the bridge deck — worn gravel shoulder, plus pre-thresholded moss weight and the anti-tiling cross-fade) and a 0.125 m detail mask around the ribbons carrying footstep phase, lateral offset and edge grain for wheel ruts and alternating footprints (bump-mapped). A third RGBA terrain mask (same grid; fetched only inside the ridge/creek rectangle) carries wet creek-bank mud, stream-bed gravel, steep-face rock and the bridge underside: rock re-uses the stony layer projected along the face's dominant horizontal axis with strata banding (no top-down stretching), the bed uses it at a finer scale, mud darkens the litter layer, deep gully ground and the underside of the bridge are darkened, and no trail is painted on banks, steep faces or under the bridge. The mask also carries an `edge` channel — the undergrowth band, 0.45–4.8 m outside the walk-mesh — that only the CPU placement reads. The fragment shader evaluates no per-fragment noise: it fetches the 0.25 m mask (and the detail mask only inside the trail footprint), then only the layers with weight — forest litter takes two albedo scales (second rotated) cross-faded by the baked blend, every other layer one scale — with a 1.3× gradient mip bias, 4× albedo / 2× normal anisotropy, and trig-based macro colour variation. Shadow reception uses a 4-fetch bilinear compare instead of the stock 16-fetch PCFSoft kernel (`GroundShadow.ts`). `GreenwakeBoundary.ts` also dresses the ridge/ramp embankment faces and creek banks with 16 deterministic, partly sunk `prop-greenwake-boulder-cluster` outcrops (ids `greenwake-boundary-rock-N`, decoration only, no colliders, always ≥ 0.8 m + footprint radius clear of every walkable and the bridge, never in the creek bed); `RegionEnvironment.visualGroundHeightAt` plants each on the lowest terrain under its footprint and sinks it slightly. `RegionEnvironment.ready` resolves when the layer textures are uploaded.

Greenwake ground cover reads the same mask. `GroundGrass` streams a pool of 12 tiles (10 m, one draw call each, ≤ 145 800 blades in total) around the focus: GPU-instanced clumps of six single-triangle blades with per-instance height/width/colour, a one-sine vertex-shader wind from the world clock, a distance fade, and distance-scaled density — each tile stores its clumps sorted by a random rank, the shader keeps ranks below `grassKeepFraction(d)` (1 within 4.5 m, 0.2 at 12 m, 0 beyond the 13.5 m fade) and the per-frame cull draws only the rank prefix that can still be alive at the tile's nearest point, so roughly half of the clumps are submitted. Grass uses a one-fetch shadow compare. None grows on the trail core, it is sparse and tufted on the worn edges and dense off-route; on the berm band it ignores the walk-mesh proximity cut, is the densest in the region and grows up to 1.7× taller. `GroundClutter` adds nine static instanced draw calls (8,156 instances, ≈195 k triangles): pebbles, twigs (including ≈140 half-buried roots along the berm), leaf piles (no shadow reception), mushrooms, ferns (wind sway; ≈1,200 of them are the dense berm band), small stones lining both trail edges, and a few softly glowing mushroom clusters (emissive 1.9, HDR) with additive halos guiding the eye along the ribbons; all use Lambert materials. Placement is deterministic and kept off the trail core; nothing casts shadows and per-frame work is the wind clock plus tile streaming. The scene still contains 173 exact native tree placements.

Grass, clutter and trail dressing follow the terrain heights (ridge, ramps, gully) and read the terrain mask: nothing grows or lies under the rope bridge, in the creek bed or on the shore gravel, almost nothing on rock faces, and wet banks keep only sparse tufts and ferns. The creek adds exactly one draw call (the water strip); the boundary rocks join the existing static prop batches.

Greenwake lighting is tuned for ACES filmic tone mapping: a warm ≈34° sun from the left of the fixed camera (1536² shadow map over a bounded 44 m square following the rendered player, ≈2.9 cm/texel, light direction fixed) throws long shadows to the right/away, a cool-sky/warm-earth hemisphere fills shadows, and a misty cool-green linear fog (22–70 m) blends into the background. Other biomes retain their region-fitted lighting. Environment disposal releases its owned geometries, shared textures/materials, vegetation and shadow target once.

The Greenwake world stack is region-parameterised: terrain field and mesh (`GroundTerrain.ts`), splat mask and material (`GroundMask.ts`, `GroundMaterial.ts`), grass, clutter, understory, water and shadow kernels (`GroundGrass.ts`, `GroundClutter.ts`, `GroundUnderstory.ts`, `GroundWater.ts`, `GroundShadow.ts`) and `RegionGround.ts` read one `BiomeProfile` per region (`BiomeProfile.ts`: relief and berm, embankments, cliff summits, carved channels and water plan, splat layers and palette, vegetation recipes, atmosphere, extra features). `Biomes.ts` resolves it: Greenwake (`GreenwakeBiome.ts`, `GreenwakeCreekShape.ts`) and the Whispering Canopy playtest variant (`CanopyBiome.ts`); every other region, and the authored canopy region, keep the generic slabs. Greenwake's ridge-top rework: the worn trail core, litter and moss gap follow the navigation ribbons only (±1.6 m, noisy edges), so wide walkables carry natural ground with short sparse grass (`interior` mask weight) and no clean outline (the tall undergrowth band starts at a wobbled 0.4 m); the creek bank rolls over into the rim with zero slope (a cubic Hermite arc), so crests read rounded. Water draws before the transparent prop batches (`renderOrder = −1`; those batches use `depthWrite = false`) so planks and trunks are never painted over; the water shader tints olive-brown shallows into dark teal, fades alpha to zero over the last 0.14 m of depth (no polygon edge at a bank), draws an irregular thin foam line at banks and rock, uses small-scale ripples scrolling along the local flow direction and a weak tinted sky reflection.

**Whispering Canopy world (`?assetPlaytest=canopy`).** The playtest variant of `whispering-canopy` (walk surfaces `canopy-trial-*`) is built by `RegionEnvironment` from `CanopyBiome`. Terrain: every walk surface is reproduced within 2 cm (flat y 0 basin, courtyard and exit path; ramps root stair 0→4 and temple descent 4→0; y 4 fig ledge and roost); the two vine-bridge decks (`canopy-bridge-deck`) are not terrain-backed, only the bridge model is drawn. Four planar non-walkable *summits* (`CanopyMassif.ts`) continue the cliff tops and ramp slopes around the walkables with hummocks and steep mossy faces, a 10.5 m rock wall west of the plunge pool and a 9 m slope north of the route form the massif backdrop, and the gorge and chasm are carved through the plateaus: the river bed lies 6.7 m (bridge A) and 8.7 m (bridge B) below the decks. Water (`CanopyRiver.ts`, one `GroundWater` mesh, one draw call): a river from the plunge pool south of the basin, north through the gorge under bridge A, east north of the roost and down the chasm under bridge B as rapids (turbulence → foam) and away south; the plunge pool south-west of the basin edge (never inside the walk-mesh, ≥ 1.9 m from it); five shallow flooded pools around the temple courtyard; a headwater stream on the cliff top. The waterfall (`CanopyWaterfall.ts`, one draw call) is a ~11 m sheet from the west cliff built from the rendered terrain so it hugs the rock, with scrolling streaks, ragged edges, whitewater and a base foam band, landing in the pool where the surface churns. Ground (`asset-source/textures/canopy/<id>/` with `provenance.json`, Poly Haven CC0): `mud_forest` humus (cross-faded), `mossy_rock` (moss on the ground, projected wet rock on faces), `roots` (worn muddy trail, bed gravel via `gray_rocks`), `leafy_grass` (undergrowth band); the layers `leafy_grass` and `gray_rocks` are downscaled to 512². Wet banks paint mud, steep ground reads as rock everywhere (`rockOnOpenSlopes`), the trail is painted only along the ribbons, and a slow dapple of light and shade drifts over the ground. Vegetation (`GroundClutter` recipes): jungle ferns, broadleaf (0.95 m, wind sway), elephant-ear big leaves in the damp, fallen logs, surface roots, mushrooms, litter and trail stones, plus taller denser grass (0.62 m blades × 1.25) in the same 12-tile pool; nothing grows on the trail core, in water or under bridges. `CanopyBoundary.ts` (`buildCanopyBoundaryPlacements(region, keepClear)`, wired into `canopyBoundaryPlacements`) adds deterministic decoration-only dressing with ids `canopy-boundary-<kind>-<n>` (no colliders once `solid-props.ts` treats `CANOPY_BOUNDARY_ID_PREFIX` as `decoration`): ferns and cliff rocks along edges and crests (small on camera-facing edges), rocks on massif faces, river banks, the plunge pool and the courtyard pools, and giant trees on level ground behind edges that face away from the camera, all ≥ 0.6 m (0.8 m by default) from every walkable and bridge, off the water and the goal ring; the region's prop set is exactly the five contract props. Atmosphere (`CanopyAtmosphere.ts`): humid green-grey fog (10–58 m), a warm key light, one `Points` draw call of falling leaves, insects/motes, waterfall spray and mist (all motion in the vertex shader from the world clock), and one additive mesh of slanted light shafts; `RegionEnvironment.setReducedEffects(true)` (and `prefers-reduced-motion`) drops the shafts and insects and thins leaves and spray. Budgets (measured): terrain 61.1 k vertices / 121.6 k triangles (Greenwake 61.3 k / 121.8 k), canopy draw calls added: terrain 1, water 1, waterfall 1, particles 1, shafts 1, clutter 8 (+ the 12-tile grass pool), mask textures 5.5 MB against Greenwake's 8.8 MB, layer textures about 39 MB against 45 MB, clutter 138–170 k triangles against Greenwake's 197 k.

`CameraDirector` is the sole gameplay-camera writer. It targets the interpolated player root plus a fixed 0.85 m torso offset and keeps the camera at the fixed `(10, 12, 14)` offset. Exploration, encounters, telegraphs, slopes, Jump and Dive use the same angle and input basis: the world moves around the centered player. Encounter anchors, telegraph locks and obstacle-driven camera retraction no longer change the view. Foreground native props use occlusion fading instead; obsolete invisible camera-raycast meshes are not constructed.

`sync` accepts an optional previous snapshot and interpolation fraction. Only consecutive simulation ticks with a non-rewinding world clock interpolate; actor roots and finite-action progress share the same sampled time, and facing takes the shortest smoothed turn. Camera placement happens after actor synchronization and uses that exact displayed root. Direct calls without history, loads, visibility changes, downed actors and discontinuities of 4 m or more snap instead of drawing movement through obstacles. Snapshot coordinates remain unchanged.

`sync` is a sample-only pass: it updates the native actors, environment, camera, screen-space LODs and any movable prop transforms for the current snapshot without issuing draw calls. The actual GPU draw happens in a separate `render()` step. Per RAF, `GameApplication.frame` runs `GameRenderer.sync(...)` first so the scene graph, camera and displayed root are settled for this pose; `StoryPresentation.update(snapshot.worldClock, { position, forward, up })` is then called with the renderer's camera basis so socket-bound presentation cues consume the same authoritative world clock the renderer just sampled; finally `GameRenderer.render()` issues the actual `WebGLRenderer.render(scene, camera)`. `CameraDirector` keeps sole authority over the gameplay camera and writes its `forward`/`right` through `getInputBasis()`; sync only copies the resolved camera pose, it never replaces it. The same ordering is followed at every initial draw site (the world-prepared snapshot, the Orun preload, and the Greenwake encounter start) so presentation always sees the sampled pose before pixels are submitted.

The engine combines immutable authored `ground.colliders`, authoritative movable-object colliders, loaded native prop solids and transient combat obstacles. `NativeSolidColliders` measures actual base-batch geometry once in canonical placement space, then transforms parts into world solids. Unknown hard props default to solid; explicitly soft reeds remain decoration. Movable props are excluded from static proxies so their engine-owned geometry is not duplicated. Native visibility changes update the scene-collider set through `syncWorldFacts`; there is no per-frame geometry extraction. Arch triangles are clipped into at-most-0.25 m height bands, avoiding the invisible wall produced by extending curved upper wood into a lower doorway. CameraDirector still owns the fixed camera and uses foreground occlusion fading, not new obstacle-driven camera motion.

Repeated native static props use `InstancedMesh`, grouped by asset ID and 16 m X/Z cells so one nearby tree does not submit every distant instance along a long route. Source-template leases are shared; batches retain independent instancing geometry, materials, opacity and visibility state. Occlusion opacity is stored per batch instance and injected into Three r169's fragment shader by multiplying `diffuseColor.a` before `#include <opaque_fragment>`; the material remains transparent and does not write depth while faded. This is validated through WebGL render-target pixels, not only by inspecting instance attributes. LOD derivatives load only when their native prop manifests are marked verified. Defaults of 160/64/24 projected pixels with 12% hysteresis remain unprofiled proposals; capture labels projected LOD measurements as unprofiled pending locked-hardware profiling.
Movable `RegionDefinition.movableObjects` entries must join one exact existing `props[]` placement and native prop manifest. The renderer omits that placement from static batches, stages one native instance at the authored `from` position (or `to` when its committed `movedFactId` is true), and updates that same root from `CombatSnapshot.movableObjects` in the application RAF. `in-flight` and `settled` positions are consumed directly; no renderer timer or tween is created. A settled local pose stays hidden until `movedFactId` commits; `syncWorldFacts` then applies the persisted destination and reveals the same instance. Movement does not alter surfaces, colliders, or routes.

`capture()` reports committed region, asset errors, missing actor/variant IDs, prop/surface/collider counts, camera state, and LOD level/measurement state without writing game state.
