# Full renderer

The renderer owns Three.js presentation of the shared `RegionDefinition`, `ActorSnapshot`, `CombatSnapshot`, `AssetManifestEntry`, and `EnvironmentRecipeDefinition`. Simulation remains the authority for movement, collision decisions, contact timing, camera-independent world state, and campaign progression.

## Public API

```ts
const renderer = new GameRenderer({ canvas, onProgress, lodPolicy? });
await renderer.loadRegion(region, assetManifestEntries, environmentRecipeDefinition);
await renderer.preloadActorVariant('orun', 'actor-orun-crowned-beast', manifest);
presentation.queueTick(combatCues); // after each fixed step
renderer.sync(combat.actors, combat, deltaSeconds, previousCombat, renderAlpha); // every RAF
presentation.presentFrame(combat, renderAlpha); // native pose already evaluated; uploads effects last
renderer.render(); // draw only after socket-bound presentation has sampled the pose
renderer.syncWorldFacts(campaignFacts);
renderer.getInputBasis();
renderer.resolveSocket(actorId, socketName);
renderer.capture();
renderer.dispose();
```

loadRegion checks the composed recipe ID, procedural layers, exact placement and ground-surface IDs, and recipe prop membership before scene commit. The region-specific environment is a code-authored composed recipe, not a guessed GLB URL. Static placements use their exact prop manifest IDs and authored transforms. Actor RegionEntity.id joins its unique runtime ActorSnapshot.id; the explicit entity.assetId resolves the native character manifest, while entity.actorId and snapshot.archetypeId identify the canonical actor definition. Multiple instance IDs may share one actor manifest and receive independent SkeletonUtils clones. A load stages assets before replacing the active scene. A newer load supersedes an older staged load; stale asset completions release their leases and cannot commit over the newer scene. Failed or superseded staging preserves the last committed region.

`preloadActorVariant` requires exact character `actorId`/`variantOf` correspondence. `ActorSnapshot.renderVariantId` is an exact asset ID; missing selected variants hide the base rig and are reported in capture data instead of falling back to the wrong form. Variant completion after a region change is released as stale.

mountCompanionPreview(host, companionId, assets, { idleActionId, loader? }) loads the exact actor manifest for that companion and returns a CompanionPreviewHandle with update(dt), actionTime, and idempotent dispose(). The caller passes the canonical actor-specific ActionId (for companion IDs, the existing catalog maps id:idle) and advances update from the existing application RAF only while the preview is active; the renderer owns no second loop. Camera framing is fitted from the loaded native bounds with a directional key and fill light. A detached/replaced host during load releases the instance and rejects as stale; a missing idle mapping fails rather than falling back.

## Native asset bytes and ownership

Every native GLB load requires a 64-character manifest `outputHash`. The loader fetches the exact runtime bytes, computes SHA-256, compares the digest before parse, checks GLB 2.0 framing, and rejects buffer/image URIs that point outside the self-contained GLB (embedded `data:` resources are allowed). Missing hashes, hash mismatches, external dependencies, malformed payloads, unskinned character models, and missing required native clips fail visibly. Only the development loader may create in-memory motion for a blocked candidate GLB with zero embedded clips and an explicit profile; it never fills a required native action mapping.

Cache identity is the asset ID plus lowercased immutable output digest and serialized playtest profile; runtimeUrl is a fetch location, not revision identity. Same-digest aliases and same-revision overlapping loads share one in-flight fetch/template. Instances hold leases on shared template geometry/material/texture resources; cache capacity evicts only unleased templates, and retired digests are disposed after their last lease. Template cleanup disposes unique geometries, materials, and referenced textures. Static prop batches own cloned instancing geometry/materials while retaining the source template lease until batch disposal.

For blocked local-playtest candidates only, `CandidateGeometrySimplifier` preserves the previous index-only reduction for skinned/morphing meshes and compacts static props after error-bounded, per-material-group simplification. Large static meshes target at most 8,000 triangles at 1% error; the error bound may retain more triangles. Compaction preserves normalized integer rows, interleaved attributes, material groups and source-buffer ownership. Native GLB bytes and hashes never change. Each instancing batch owns distinct GPU attribute identities while sharing immutable CPU storage and retaining its template lease.

The manifest's canonical action mapping is `actionToClipMapping` (`ActionId` to exact provider clip name); `requiredActionIds` must map to clips present in the native GLB. Finite clips sample `ActorSnapshot.normalizedTime`. Looping clips integrate deltas of the authoritative actor clock, using a velocity-derived rate for locomotion; duplicate clocks do not advance phase, a zero locomotion rate holds it, and a clock rewind reseeds it. Walk↔run transfers normalized gait phase between different clip durations and cross-fades. Render-frame delta advances fade weights, not gameplay action time. Aliased action IDs retain their own manifest/root-motion identity even when they share one native `AnimationClip`. Repeated finite actions resample their new normalized progress and retain the endpoint when complete. Missing native action clips throw `AnimationBindingError` rather than selecting an arbitrary clip. `playtestAnimation` remains a separate development-only profile; its generated clips do not alter canonical mappings or required-action evidence.

Per-action root motion must have verified metadata. For `native-root-motion` and `authored-curve`, the controller requires `rootNodeName` and finite curve samples, and captures the canonical root bind before playback. By default it restores the full bind translation after each animation sample. Explicit `preserveVerticalMotion: true` removes horizontal travel while preserving the native vertical crouch and bob; it does not transfer root travel into simulation state. "Vertical" is the actor-space up axis expressed in the root node's parent frame, captured from the bind hierarchy: parent-local Y for Aren, local Z for Yara's Z-up Tripo/Mixamo armature (whose kneeling Sap Lance previously floated ~0.5 m because its drop was reset as if horizontal). Axis-aligned rigs keep bit-identical horizontal resets. Simulation actor position remains the only world-displacement authority. Missing or unverified root-motion policy fails closed when that action is played. `in-place` clips also require verified per-action declaration. Playtest-generated clips contain only quaternion tracks and receive runtime-only in-place policy; this is not release evidence. Authored contact records are exposed only for the currently active action; no contact timing or gameplay event is inferred from render delta.
Locomotion cadence reads the clip's authored ground speed in actor X/Z: `AnimationController` caches `authoredPlanarSpeed` per verified `native-root-motion` walk/run/strafe action when it captures the root bindings, and `ActorAnimationDriver` (`nativeLocomotionPlaybackRate`) plays the loop at actor speed divided by that cached value. The cache carries the Hips curve displacement through the root node's bind parent-to-actor matrix (rotation and scale) and then multiplies by the manifest `coordinateTransform.scale`. An earlier version read the displacement in the parent's local X/Z, which is only the actor's ground plane when the parent adds no rotation; Vesper's native root parent rotates its local −Y onto actor +X, so the speed (and with it the playback rate) was taken from the wrong axes. A permanent regression drives the actual controller and driver with a rotated and scaled root parent: before the fix the observed phase stayed at 0 where 0.5 is expected, after it reaches 0.5 and the vertical bob and root compensation are correct. A provisional smoke through the real `GLTFLoader` and `AnimationController` on the exported Vesper and Sakda candidates observed that both scene wrappers map native +X to runtime +Z, that the planted walk toes travel along −Z, and that the cache returns 0 for Sakda walk/run and Vesper walk and about 4e−7 m/s for Vesper run (so the bob causes no unintended playback scaling); no manifest heading change was needed. These observations were made on assets that were still being regenerated, so the final integrated geometry and browser runs are still pending.
The local Greenwake development playtest binds the user-supplied Aren movement clips and donated Idle/Cheer/Defeat to their semantic actions. Its 65-joint skin and measured Hips curves support local action routing, root-motion compensation and locomotion cadence. The candidate remains evidence-blocked, is not exported to production manifests, and leaves unrelated authored actions unbound.

### Sockets and the `cast` head binding

Explicit manifest socket names resolve against the native scene. For a blocked character lacking an explicit `cast` socket, `NativeAssetLoader` also resolves `playtestAnimation.headBoneName`, allowing GLTFLoader's sanitized form of that name, and accepts only the actual native Bone. ## Scene and camera behavior

Ground and water vertices use absolute world coordinates from authored `GroundSurfaceDefinition.points`; `elevation` is not added again. Rendering uses the same first-point polygon fan triangles as physics `groundHeightAt`, with winding corrected for visible upward faces. No decorative height is introduced apart from authored geometry. Restored/partial facts are applied through recipe restoration keys and authored `visibleWhen` changes; the renderer does not infer progression. Every authored `REGIONS` entry now publishes partial/restored boolean facts; `RegionEnvironment.syncWorldFacts` retints authored surface materials from those booleans (restored → 10% `PARTIAL_RESTORATION_TINT`, partial → 20%, neither → base color). The browser fixture verifies the partial/restored/neutral tint transition against the existing real-renderer code path.

Greenwake's ground is a visual terrain, independent of the walk-mesh (`src/world/GroundTerrain.ts`, `RegionGround.ts`). A deterministic mesh covers `region.bounds` plus a 16 m margin. The 1 m grid refines walkable boundaries, embankments and carved channels to 0.25 m; up to 600 additional coarse cells are refined, worst-first, when five analytic-height probes exceed 0.25 m error. Coplanar cells and strips are merged only within 1e-6 m, retaining every shared boundary vertex. Coarse neighbours triangulate through those vertices: no T-junction cracks or extra ground plates.

Every terrain-backed walkable follows its authored plane within 2 cm on the rendered mesh. Greenwake's forest floor now ends at the ramp foot; the adjoining bank and boar thicket continue the root-ramp plane instead of overlapping a hidden y=0 floor or meeting it in a vertical step. The detour ribbon and navigation include the bank foot, and Ember Crossing's flat arena stays south of the grade. Ground-placed native props add only visual relief beyond their authored walk-surface height, never the ramp height twice. Bridge decks remain separate native geometry, with the gully beneath them.

The existing 0.36 m shoulder protects walkable heights before the embankment blends into surrounding relief. Greenwake's creek still carves the ridge/gateway gap, with a bed near −1.3 m and one transparent water strip 0.2 m above it; the carve fades out at walkable footprints. `GroundMaterial` retains the four CC0 Poly Haven layers and provenance under `asset-source/textures/greenwake/`, baked trail/detail/terrain masks, dominant-axis rock projection, depth-tinted water, bank foam and the four-fetch shadow comparison. Grass, trail dressing and boundary outcrops consume the same terrain/masks. Visual relief does not grant walkability.

Greenwake ground cover reads the same mask. `GroundGrass` streams a pool of 12 tiles (10 m, one draw call each, ≤ 145 800 blades in total) around the focus: GPU-instanced clumps of six single-triangle blades with per-instance height/width/colour, a one-sine vertex-shader wind from the world clock, a distance fade, and distance-scaled density — each tile stores its clumps sorted by a random rank, the shader keeps ranks below `grassKeepFraction(d)` (1 within 4.5 m, 0.2 at 12 m, 0 beyond the 13.5 m fade) and the per-frame cull draws only the rank prefix that can still be alive at the tile's nearest point, so roughly half of the clumps are submitted. Grass uses a one-fetch shadow compare. None grows on the trail core, it is sparse and tufted on the worn edges and dense off-route; on the berm band it ignores the walk-mesh proximity cut, is the densest in the region and grows up to 1.7× taller. `GroundClutter` adds nine static instanced draw calls (8,156 instances, ≈195 k triangles): pebbles, twigs (including ≈140 half-buried roots along the berm), leaf piles (no shadow reception), mushrooms, ferns (wind sway; ≈1,200 of them are the dense berm band), small stones lining both trail edges, and a few softly glowing mushroom clusters (emissive 1.9, HDR) with additive halos guiding the eye along the ribbons; all use Lambert materials. Placement is deterministic and kept off the trail core; nothing casts shadows and per-frame work is the wind clock plus tile streaming. The scene still contains 173 exact native tree placements.

Grass, clutter and trail dressing follow the terrain heights (ridge, ramps, gully) and read the terrain mask: nothing grows or lies under the rope bridge, in the creek bed or on the shore gravel, almost nothing on rock faces, and wet banks keep only sparse tufts and ferns. The creek adds exactly one draw call (the water strip); the boundary rocks join the existing static prop batches.

Greenwake lighting is tuned for ACES filmic tone mapping: a warm ≈34° sun from the left of the fixed camera (1536² shadow map over a bounded 44 m square following the rendered player, ≈2.9 cm/texel, light direction fixed) throws long shadows to the right/away, a cool-sky/warm-earth hemisphere fills shadows, and a misty cool-green linear fog (22–70 m) blends into the background. `CameraDirector` is the sole gameplay-camera writer. It targets the interpolated player root plus a fixed 0.85 m torso offset and keeps the camera at the fixed `GAMEPLAY_OFFSET` `(7, 7.2, 10)` from that target — ~14 m follow distance at 30.5° elevation — with FOV `GAMEPLAY_FOV` 49.5°. Camera follow polish (all gated by `dt > 0` and off under reduced motion, where the target is the rendered root exactly). Height follows the rendered root through a critically damped spring (ω = 15 rad/s): a 0.4 m step trails by at most the step, never overshoots, is under 4 cm after 0.35 s and under 4 mm after 1 s; a steady 2 m/s climb trails by 2/ω ≈ 0.133 s of travel (0.24–0.29 m); the trail is clamped to 0.9 m, and a vertical jump above 3 m or a horizontal jump above 6 m between two frames (respawn, teleport) snaps. The ground plane is never lagged. A look-ahead of 0.085 s of planar velocity (capped at 0.55 m, critically damped at ω = 5.5 rad/s, about 0.51 m at 6 m/s, under 5 mm 2.5 s after stopping) shifts the target along the velocity. The lens opens by up to 3° between 4.8 and 5.8 m/s (sprint) and by up to 2.5° mid-dodge (a `dive-roll`/`dodge` action, sine of its normalized time), never more than 4° together, with attack 7/s and release 4.5/s. Establishing shot (`src/rendering/EstablishingShot.ts` holds the geometry; `CameraDirector` poses the camera, `GameRenderer` plans the shot and owns the fog). `GameRenderer.beginEstablishingShot({ seconds, reducedMotion })` starts a camera sweep that `render()` advances with real time (`performance.now`, clamped to 0.1 s per frame); `skipEstablishingShot()` jumps to the gameplay framing and `establishingShotActive` is true while it runs; a second begin restarts from the true framing. Reduced motion (option or the renderer setting) and a non-positive duration are a no-op, and enabling reduced motion mid-shot ends it. The sweep interpolates azimuth (from the planned start azimuth, `sweep` radians around the gameplay azimuth), horizontal distance, height and the look point with one cubic ease-in-out that has zero slope at both ends, and the lens from 6° narrower; the last frame is the gameplay pose, so it ends on exactly the normal follow framing (position, orientation and FOV match to 1e-9 in `CameraDirector-motion.test.ts`). The simulation is untouched; the caller keeps it paused. Region replacement ends a running shot.

Planning (`planEstablishingShot`): the look point is 60 % of the way from the middle of the walkable surfaces' bounds to the player, so the player's surroundings and the route ahead fill the frame. Candidates are four distances (the widest is `0.3 × walkable diagonal / tan(fov/2)` clamped to 44–80 m, then 85 %, 70 % and 44 m), six sweeps (±1.2, ±1.9, ±2.6 rad) and two pitches (32° plus one degree for every metre by which the tallest static prop within that distance of the look point — instance matrices of the placement batches, measured once per shot — exceeds 12 m, up to 54°, and that pitch plus 8°), so giant-tree canopies are seen from above instead of across their crowns. The world edge must never be in frame: each candidate is checked at 40 steps of the sweep (eased progress 0 to 0.8; beyond that the pose is within 20 % of the gameplay framing, whose own view is not the shot's to change) by casting the four frame corners and the middle of the top edge, with that step's lens, against the ground plane, and counting every ray that lands past the drawn terrain mesh (the bounds of the `<biome>-terrain` mesh; region bounds + 12 m for regions without one). Every such ray must be at least 90 % fogged at its step; the check uses the fog's 90 %-of-range point (about 97 % opacity) and the view depth along the camera axis, as the fog shader does. A candidate is acceptable when the fog spread it allows reaches the spread the look point needs; among acceptable candidates the fewest rays past the terrain wins, then the larger distance and the first frame that looks most toward the region's middle, and with none acceptable the candidate with the most headroom wins. Fog: the sweep scales the scene `Fog` near/far outward by the chosen spread (the look point's 70 %-opaque distance, near + 0.64 × (far − near), at least 1.3× the start distance, up to 3× the authored values and never more than the edge check allows) and eases that scale back to 1 with the same ease; the object is only scaled, never replaced, and `render()` restores the authored near/far exactly once the sweep has ended by any route (end of time, skip, reduced motion). `tests/rendering/EstablishingShot.test.ts` re-checks nine synthetic region/fog/player cases with an independent `PerspectiveCamera` unprojection (every ray past the terrain at least 90 % fogged at 60 sampled steps) and the planner's invariants.

Presentation-only actor motion polish (`src/rendering/ActorMotionSmoothing.ts`, one preallocated record per displayed instance, no per-frame allocation; the simulation, hit geometry and snapshots never see it). Drawn height: the simulation snaps up and down stairs and ledges by up to 0.45 m in one tick, so the drawn root absorbs any rise or fall faster than 4 m/s (slopes and stairs of a walking gait pass untouched) into an offset that a critically damped spring (ω = 14 rad/s) pulls to zero: a 0.45 m pop becomes a monotonic ramp that is within 1.2 cm after 0.5 s with no overshoot. `sync` is a sample-only pass: it updates the native actors, environment, camera, screen-space LODs and any movable prop transforms for the current snapshot without issuing draw calls. The actual GPU draw happens in a separate `render()` step. Per RAF, `GameApplication.frame` runs `GameRenderer.sync(...)` first so the scene graph, camera and displayed root are settled for this pose; `StoryPresentation.update(snapshot.worldClock, { position, forward, up })` is then called with the renderer's camera basis so socket-bound presentation cues consume the same authoritative world clock the renderer just sampled; finally `GameRenderer.render()` issues the actual `WebGLRenderer.render(scene, camera)`. `CameraDirector` keeps sole authority over the gameplay camera and writes its `forward`/`right` through `getInputBasis()`; sync only copies the resolved camera pose, it never replaces it. The same ordering is followed at every initial draw site (the world-prepared snapshot, the Orun preload, and the Greenwake encounter start) so presentation always sees the sampled pose before pixels are submitted.

The engine combines immutable authored `ground.colliders`, authoritative movable-object colliders, loaded native prop solids and transient combat obstacles. `NativeSolidColliders` measures actual base-batch geometry once in canonical placement space, then transforms parts into world solids. Unknown hard props default to solid; explicitly soft reeds remain decoration. Movable props are excluded from static proxies so their engine-owned geometry is not duplicated. Native visibility changes update the scene-collider set through `syncWorldFacts`; there is no per-frame geometry extraction. Arch triangles are clipped into at-most-0.25 m height bands, avoiding the invisible wall produced by extending curved upper wood into a lower doorway. CameraDirector still owns the fixed camera and uses foreground occlusion fading, not new obstacle-driven camera motion.

`NativeSupportFields` measures native bridge decks and solid prop tops on a 0.125 m grid once at load. Connected, slope-limited deck samples exclude rails/posts and fill small internal plank gaps, never missing model ends. These fields replace matching authored bridge fallback surfaces and travel with the visible scene-collider set into `CombatEngine.setSceneColliders`. `GameRenderer.getNativeSupportFields()` exposes the current fields; changing regions or visibility removes stale support.

Landing queries require a reachable top, full capsule clearance, supported rim and a swept clear jump arc. Walking off a native top starts gravity-driven falling; removing its support also drops the player without spending jump mana. Lip slides cannot push the capsule through authored walls. Real Greenwake rope-bridge placement and Canopy bridge B endpoints are aligned to their measured decks. The existing mire-bank rock is reused for accessible Greenwake, Canopy, Moonpine and Mistveil props; Grove uses its native basin. These candidates remain evidence-blocked.

Repeated native static props use `InstancedMesh`, grouped by asset ID and 16 m X/Z cells so one nearby tree does not submit every distant instance along a long route. Source-template leases are shared; batches retain independent instancing geometry, materials, opacity and visibility state. Occlusion opacity is stored per batch instance and injected into Three r169's fragment shader by multiplying `diffuseColor.a` before `#include <opaque_fragment>`; the material remains transparent and does not write depth while faded. This is validated through WebGL render-target pixels, not only by inspecting instance attributes. LOD derivatives load only when their native prop manifests are marked verified. Defaults of 160/64/24 projected pixels with 12% hysteresis remain unprofiled proposals; capture labels projected LOD measurements as unprofiled pending locked-hardware profiling.
Movable `RegionDefinition.movableObjects` entries must join one exact existing `props[]` placement and native prop manifest. The renderer omits that placement from static batches, stages one native instance at the authored `from` position (or `to` when its committed `movedFactId` is true), and updates that same root from `CombatSnapshot.movableObjects` in the application RAF. `in-flight` and `settled` positions are consumed directly; no renderer timer or tween is created. A settled local pose stays hidden until `movedFactId` commits; `syncWorldFacts` then applies the persisted destination and reveals the same instance. Movement does not alter surfaces, colliders, or routes.

## Atmosphere, foliage and occlusion fade

Atmosphere is owned by `src/world/AtmosphericSky.ts` (sky dome with zenith/horizon/ground gradient, sun disc + glow, clouds) and the per-region `HeightFogShader`, `LightShaftsShader` and `ColorGradeShader`. `RegionAtmosphereBridge.configureRegionAtmosphere` runs on region load; `updateRegionShafts` is allocation-free per frame. Each biome profile carries its own `sky`, `heightFog`, `grade` and `lightShafts` settings. The PostFX pass order is `RenderPass` → `UnrealBloom` → height fog → light shafts → impulse → grade → `OutputPass`. Light shafts radially blur toward the projected sun (`projectSunScreen`; a sun behind the camera reports (9, 9)), and only taps within `SUN_FEED_RADIUS` 0.28 UV of the sun feed a ray, so bright VFX, sigils and glowing actors are never smeared. `updateRegionShafts` fades the strength to zero as the sun moves 0.25 UV outside the frame, which disables the pass; the elevated gameplay camera keeps the sun out of view, so shafts appear in wide shots (establishing shot) and cost nothing in play. An earlier fallback pulled every pixel toward the screen centre whenever the sun was off-screen, which smeared bright effects at the player into ringed discs; it is removed. The height-fog distance term pools near the ground as `pow(vertical, mix(2.4, 1.1, groundBias)) * smoothstep(0, nearFloor, vertical)` (uniforms `uGroundBias`, `uNearFloor`), keeping the play area clear. Greenwake is retuned for golden hour: sun `0xffc878` ×3.6 at offset (−52, 18, 22) ≈22° elevation, hemisphere `0x6e8aac`/`0x46342a` ×0.85, cool fill `0x6f8aa8` ×0.32, fog 28–84 m, sky zenith `0x2a4458` / horizon `0xd2a26a`, cloud coverage 0.35, height fog `0x5e7088` density 0.045, grade saturation 1.06 vignette 0.18, light shafts 0.85. Centre luminance measured live: 62/255 with the full chain vs 35 with fog+grade off. The closer gameplay pose makes the old 90 % edge-fog contract unreachable on canopy, so the establishing shot contract is now ≥70 % (worst measured 83 %, canopy), with `MIN_DISTANCE` 40 m.

The scene geometry retains ×2 MSAA in its own half-float target. A resolved `TexturePass` feeds depth-free, single-sample composer buffers; bloom, fog, shafts, impulse and grading no longer repeatedly resolve multisampled fullscreen targets. Scene compilation and one-pixel GPU preparation use the geometry target. Resizing changes logical dimensions and pixel ratio together through `setDrawingBufferSize`; scene and composer buffers share the same physical size.


Foliage variation and wind live in `PropInstanceVariation.ts` (deterministic per-instance tint, scale, lean and wind phase) and a vertex shader in `NativeAssetLoader.ts` that reads `uFoliageMeshHeight` from each mesh's bounding box and uses `instanceMatrix[3].x/.z` as a per-instance wind phase. The world wind is driven by `GameRenderer.setFoliageWorldWind(renderWorldTimeSeconds)`; reduced motion freezes the wind through `setFoliageReducedMotion`. Clustered boundary placement reuses the same prop entries in Greenwake, canopy, bamboo, grove, moonpine and mistveil.

Occlusion fade is `InstanceVisibility.advanceFade`: tweened per-instance opacity stored on the static `InstancedMesh` and injected into Three r169's fragment shader by multiplying `diffuseColor.a` before `#include <opaque_fragment>`, so the material stays transparent and does not write depth while faded. Defaults remain 160/64/24 projected pixels with 12 % hysteresis; LOD derivatives still load only when their native prop manifests are marked verified.

### Character shadows, contact shadows and foot grounding

Every displayed character mesh casts and receives the sun shadow. The hero variants loaded through `preloadActorVariant`/`setPlayerHero` were the gap (their `SkinnedMesh` never had `castShadow`), so the flags are now set where an instance is created (`castShadows` in `GameRenderer`), not per frame; afterimages and VFX shells keep their explicit non-casting flags.

`ContactShadows` adds a soft ground-contact occlusion under every visible actor: one `InstancedMesh` (fixed pool of 64, one extra draw call, no texture reads) whose shader falls off as `(1 − r²)²`, peak darkening 0.42, `depthWrite` off, `polygonOffset`, drawn between the water and the transparent props so trunks, decks and grass blades in front of it still occlude it. Each quad is sized once per loaded instance from the bind-pose footprint (the lowest half of the skinned body's vertices, outermost 4 % trimmed; a scabbard or prop hanging on a bone does not count), follows the displayed interpolated root and its yaw, is placed on the engine ground under the actor (`groundHeightAt` over the region arena plus native support fields, with the rendered terrain as fallback) and tilts to the ground normal (≤ 35°). Opacity falls to zero as the root rises above that ground (walkers 0.03→0.8 m, so a 1.25 m jump shows none at its apex; actors with a `MONSTER_HOVER` profile 0.02→0.25 m, so hovering flyers such as Vara never show one while a settled/downed one does). The pool belongs to the region world and is disposed with it.

`FootGrounding` is presentation-only two-bone IK for Mixamo-named biped rigs (the playable hero variants; rigs without a complete `mixamorig:` hip and both legs, such as the Tripo-rigged companion bodies, are left alone). `AnimationController` gained a `setGrounding` slot with two calls: `restore()` before every mixer evaluation puts back the clip values the previous pass overwrote (the mixer skips unchanged clip values and root-motion compensation reads the hip height, so a corrected pose must never be visible to either), and `apply(dt)` runs after the clip, root-motion compensation and `postPose` (`setPostPose` is unchanged). All weights fade (in 0.17 s, out 0.07 s), foot targets are slew-limited, and a teleport, hidden actor, jump phase, roll/vault/slide/defeat action, downed actor or root more than 0.15 m above the ground fades the correction out. Claw Combo, Side Charge, Roar, Black Sap Trail and Koro's five attacks use the generic slots (rock throw = shoot, platform charge = run revs + dive, leap = jump, log sweep = slash, falling branch = roar; the branch itself is drawn by the effect).
- **Story stances** (`StoryActorAnimation.ts`, pure, world-clock driven, story assets only): Asha prowls (`asha-stalk`) in boss phase 1, stands in `asha-corrupted-idle` from phase 2, plays `asha-cleanse` once over 2.8 s from the first frame of `chapterStatus` cleansed / reunion and then holds `asha-bond-idle`; Tali trembles (the hurt clip's dazed hold, +/-0.045 at 5 Hz) while `in-danger`, nuzzles once (2.4 s) on `reunion`, and plays `tali-play` while no living hostile is visible; Marek plays the talking idle of the current line (`GameRenderer.setNpcTalk(actorId, 'relaxed' | 'explain' | 'point' | 'guarded' | undefined)`, called by the application) with `npc-talk-point` as a one-shot. A status already in force at the first sighting (load) holds the settled stance instead of replaying it. `isMonsterDefeated` is false for cleansed / reunion / subdued / kneeling / in-danger / sheltered, so a nonlethal status never plays `monster-death`. Attacks, roars, staggers, weak-point holds, reactions and the flinch overlay stay with the generic resolver; an actor in a cleanse / reunion / in-danger status or with a finite job is exempt from animation LOD skipping.
- **Foliage** (`FoliagePresentation.ts`, `InstanceVisibility.ts`, `NativeAssetLoader.loadStaticBatch(.., limits)`): static prop batches are still one `InstancedMesh` per mesh per 16 m cell. `prop-bamboo-grove-cluster` uses `fade: 'dither'` (opaque, depth-writing material; an occluding instance is thinned by a 4x4 Bayer screen-door discard) instead of the default transparent no-depth-write blend, and instances farther than 64 m from the camera are not drawn (6 % hysteresis; matrices are rewritten only for instances whose state changed). The grove GLB's own material is opaque (`alphaMode` absent). The fade-alpha comparison now uses the float32 value, so a steady fade uploads nothing (it compared a double with a Float32Array element before).
- **Hunters**: `actor-camp-hunter-melee` / `-ranged` are not in `asset-source/playtests/bamboo.json` yet, so no hunter clip plan or kneel/subdued stance is wired; the story layer reads `chapterStatus` subdued / kneeling already and never treats them as a defeat.
