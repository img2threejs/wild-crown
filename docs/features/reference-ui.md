# Reference UI implementation

This document describes the DOM-only `GameUI` surface in `src/ui/`. It is a presentation layer over the shared `GameViewModel`; it does not calculate quest, party, unlock, save, or ending progression. Runtime operations are emitted as typed `UIAction` values to the application owner.

## Lifecycle API

```ts
this.ui = mountGameUI(this.overlay, {
  onAction: action => { void this.dispatch(action); },
  onPreviewHost: (host, companionId) => this.preview(host, companionId),
});

this.ui.render(nextViewModel);
this.ui.updateGamepad(gamepad);
this.ui.destroy();
```

`GameUIOptions.onPreviewHost` is optional and returns an optional disposer. It is called only for a mounted Companions preview and receives the selected `CompanionId` (or `null` when no party member is selected). The application's synchronous adapter bridges that contract to renderer `mountCompanionPreview(host, companionId, assets, { idleActionId, loader? })`, which resolves a handle with `update(dt)`, read-only `actionTime`, and idempotent `dispose()`. The adapter owns late-resolution cancellation and updates the handle from the application's existing frame only while the preview screen is active; GameUI does not create another animation loop. The component-only empty state says “Waiting for character renderer”; it never paints a still image or primitive model as a 3D preview.

`render` uses a value signature of the `GameViewModel` to avoid unnecessary work. During a primary-button press on an action button or keyed input/select it defers view-model renders through pointer completion, preventing DOM replacement between pointerdown and click. A pending screen transition cancels the stale action. For same-screen pointer state, a click renders the latest pending view model before dispatching an action computed from the pre-update model; if no click occurs, the pending render flushes on the next frame. A focused keyed control is reconciled in place (including current input value and text selection) when its view remains, then refocused without scrolling. A screen transition focuses its first visible control when no keyed match exists. Pointer and keyboard listeners, deferred frame work and preview resources are released by `destroy`.

## View-model screens and action boundary

- **Title / loading / error:** New Game opens hero/companion selection; confirmation creates a new journey, while Back preserves existing saves. Default development and static builds share the playable candidate campaign and its browser-local IndexedDB scope. Continue loads its newest committed campaign slot; Load Game selects another. The persistent candidate banner remains visible. Loading renders the selected region's scene (`loadingSceneMarkup`, see [story-review.md](story-review.md)) with progress, phase label, detail and lore. Recoverable errors render Retry only with an operation ID. Errors expose `UIAction.return-title`; Settings and Import are omitted during pending durable-event failure. Save/Load apply only to real chapter campaigns, never replay-isolated Trials. Resume restores safe checkpoint progress rather than exact live combat/position.
- **World-panel navigation:** the required `canOpenWorldPanels` capability controls Map/Journal/Companions toolbar visibility and keyboard/gamepad world shortcuts. The application projects it from its initialized-world policy and remains the authority for rejecting stale/programmatic actions. Title/error Settings retains Settings and Back but does not expose empty world panels. A component/simulator fixture can explicitly enable its own navigation without claiming native asset readiness.
- **Exploration / boss HUD:** vitality, numeric mana/maxMana, Instinct, engine-owned skill readiness, encounter roster/trial progress, objective, traveling party, and boss corruption/ferocity come from the current view model. Interaction prompts use authored `inputHint`/`activation` with the active `GameViewModel.bindings`; `heavy`/`ability` hints render informational RuntimeInput prompts and never dispatch direct resolve actions. Any prompt with `requiresCompanionCommand` or `playerActionId` is always informational and never falls back to a generic E/interact button. Only a direct interact prompt emits `UIAction.interact`.
- **Spent interactions:** a non-repeatable prompt is withdrawn as soon as the engine has emitted its world event (`CombatEngine.interactionSpent`, read from the same `seenWorldKeys` record the engine refuses repeats with), not only once the campaign writes `interaction:<id>`. Fragment, restoration and rescue interactions never write that fact, and semantic ones write it only after the asynchronous commit; before this rule a second press on the Sky fragment (or a fast double press on any interaction) reached the engine refusal and stopped the game with “The authored interaction is not available…”.
- **Map:** two views of one tab. **Area** (default) is the survey sheet of the loaded region from `GameViewModel.areaMap` (`ChapterFlow.areaMapOf`): walk surfaces, trails, exits and objective positions projected so screen-up is the camera's forward direction, padded 6 m, on a lettered/numbered grid whose square (5–100 m, at most 10 per axis) is snapped so the sheet ends on whole squares. Grid codes (e.g. `B2`) are computed once there and shared by the map, the Journal and the HUD. The current objective's pin is labelled and the magenta route follows the authored trails to it; locked exits show their requirement. **World** is the illustrated Erya map: region markers use map unlock state and an unlocked authored entrance ID, travel emits `{type: 'travel', regionId, entranceId}`, and the configured movement bindings pan the image without changing campaign state. The world-map image is the English, concept-approved M01 asset. The right sheet is the current objective (quest, `Step n of N`, grid, distance) and the quest's steps; hovering or focusing a step highlights its pin.
- **Journal:** the left sheet repeats the current objective and lists the story so far, side quests and world state; the right sheet is the quest log (`GameViewModel.questLog`): each step is drawn solid when current, plain when open, struck through when done, with its grid code and a Track button that emits a typed `track-objective` action. The HUD objective panel without a chapter objective reads the same quest log.
- **Menu tabs:** Map, Journal, Companions, Hub and Settings share one tab bar; switching tabs replaces the page and Back/Escape leaves the menu for the screen that opened it (see [application.md](application.md)).
- **Visual system:** the frame (dark map case, `--wc-frame`) carries the HUD and menu chrome over the scene; every page of content is an unbleached survey sheet (`.wc-sheet`, `--wc-paper` #ECE5D3, ink #1E231B) that re-points the contextual tokens. The magenta route colour (`--wc-route` #A8174F) is reserved for the current objective, live selection and primary actions; state is drawn by line form, not hue alone. Type is self-hosted through `@fontsource`: Barlow (UI), Barlow Condensed (headings, tabs, labels) and Alegreya italic (lore and descriptions). Icons are one 24-unit line set (`src/ui/icons.ts`) drawn in `currentColor`.
- **Companions:** choose exactly one of six helpers in hero select; `settings.heroCompanions` remembers each hero separately. Continuing a journey preserves that run's saved companion. C opens the one-equipped/reserve panel; exile and active story/trial/ambient combat refuse replacement. The command wheel addresses only that helper, with no role tabs or cycling controls. `GameViewModel.abilities` exposes all 20 implemented skills with one element each, effect, automatic/manual policy, actual cost, cooldown and refusal reason. **Preview animation + VFX** plays the exact native gesture without gameplay effects. **Use now · return to game** issues the real typed command and closes the paused panel only on success. C/R hints resolve from current bindings. Story recruitment/Bond remains separate from roster access. Nyra's authored hidden route stays a separate HUD interaction; Tali is not a party entry.
- **Settings:** audio, accessibility, subtitle, glyph, motion, target-assist and deadzone controls emit typed `update-settings` patches. Keyboard/Mouse and Gamepad bindings render from separate `InputBindingMaps`; remapping emits `{type: 'remap', device, actionId, binding}`. Gamepad binding fields are read-only and capture a physical button while focused. Conflict/error text is shown from `GameViewModel.error`, not synthesized by the UI.
- **Save/load:** slots, continue state, labels, timestamps and chapter/region metadata come from `GameViewModel.saves`. Save, load, slot creation, import and export emit their corresponding typed actions; the UI does not report mock persistence success.
- **Dialogue / choice / ending / credits:** dialogue lines, speaker IDs, choice options, ending title and summary come from the view model. Continue, skip, choose, credits and return-to-title emit typed actions.
- **Dialogue line progression:** the active beat's `lines` are presented in authored order. Continue emits `{type: 'advance-dialogue', beatId}` and the application walks one line per Continue; the beat itself only advances (via `next`, into a choice, into the prologue encounter, or out) after the final line has been shown. The view model carries the active line position as a presentation-only `dialogueLineIndex` (required, zero-based) alongside the authored `dialogue` reference; the UI selects `dialogue.lines[viewModel.dialogueLineIndex]` for the active line, and `gameUiSignature` includes `dialogueLineIndex` so the same beat re-renders when the index advances. Application presentation state (the active line index) is in-memory only — it is never persisted, never inspected by the campaign authority, and is reset to 0 on every dialogue assignment, advance to the next beat, return-to-title, and cinematic skip so stale indices cannot leak across lifecycle changes.
- **Prologue intro:** a new Greenwake run presents the existing `prologue-vision` dialogue and pauses gameplay until its lines are advanced; after the final line, the existing Greenwake encounter begins. This run-start dialogue is not replayed by the transition-cue scheduler.
- **Pause in local playtests:** Save Game and Load Game stay visible but disabled, with the reason as visible text (`aria-describedby`): local asset playtests never write campaign saves, so the controls would have been silently rejected.
- **Dialogue presentation:** the card shows the speaker crest (companion portrait, hero crest or monogram), the speaker label, a `n / total` counter and the line as three-word groups that fade in one after another (CSS only; plain text under reduced motion). It honours `settings.subtitleSize` (small/medium/large), `settings.subtitleBackground` (off/translucent/solid) and `settings.subtitleSpeakerLabels`; `settings.subtitles` and `echoSubtitles` do not apply because dialogue is the only channel of the story text. Each line is announced through a persistent `role="status"` live region that lives outside the screen layers, so replacing the card never drops the announcement; leaving the dialogue clears it.
- **Settings switches:** the seven on/off settings are `role="switch"` buttons with `aria-checked` and `aria-labelledby` pointing at the setting label and the button, so the accessible name is e.g. “Reduced Motion On”.
- **Keys the UI handles stay in the UI:** Escape and the Pause binding, when handled by `GameUI` (pause, resume, close a panel), call `stopImmediatePropagation()`. Resuming enables gameplay input synchronously, so without this the same keydown reached `RuntimeInput` and paused the game again straight away (observed live before the fix).
- **Settings layout:** every settings row shares one control column (`clamp(8.75rem, 40%, 12rem)`), so select, range, binding input and switch controls have one width: at 1440 × 900 and 390 × 844 every select shows its widest option and none of the 29 binding inputs clips.
- **Map intro and establishing shot:** see the section below. `map-intro` is a view-model screen; the establishing shot is `scene.establishingShot` on the `game` screen.

Keyboard/Mouse and Gamepad settings show independent persisted maps. Keyboard shortcuts read from `.bindings.keyboard`; gamepad menu shortcuts read rising edges from `.bindings.gamepad`; the HUD control hints and context interaction key come from the active map. D-pad edges remain UI navigation, and gameplay actions are owned by RuntimeInput. There is no hidden single-map fallback.

## Screen transitions and motion

`GameUI` hosts two persistent layers (`.wc-layer`) under `.wc-ui`. The front layer shows the current screen; the other plays the outgoing screen's exit and then empties. A screen change is a change of *screen key* (`screenKey()`: the view-model screen, with `loading`/`shot` overriding it, plus the UI-local `save`/`load`); everything else is a same-screen update.

- **Screen change:** the outgoing layer becomes `inert` and `aria-hidden` and plays `.wc-leave` (≤ 220 ms, `LEAVE_MS`); the other layer takes the new content, the front and `.wc-enter` (layer animation ≤ 380 ms; scenes wait 130 ms so the exit reads first). Focus moves to the incoming screen's control with the same `data-focus-key`, else its first control. `.wc-enter` is removed after `ENTER_SETTLE_MS` (scene 2700 ms so the staggered title can finish, overlay 520 ms, HUD 700 ms); the leaving layer is emptied and hidden after 260 ms. A newer screen change bumps a generation token, clears the older change's timers and drops a ghost still on its way out; the preview of a leaving hero-select/companions screen is disposed when its layer is retired (immediately if superseded).
- **Same-screen updates** keep today's behaviour: the `render()` value signature skips unchanged models, HUD updates replace the layer's children without any entrance animation, loading/intro/shot (and any screen still entering) are patched in place (`morphChildren`) so running animations keep their place, and a control focused by the user is reconciled in place. Layout is read only when a control actually held focus.
- **Kinds:** scenes (title, map/hero select, intro, loading, dialogue, outcomes) fade (360 ms; 120 ms delay after another screen so the exit reads first); panels (pause, map, journal, companions, settings, credits, save, load) fade in over the dimmed, blurred frame (220 ms); the gameplay HUD only fades (160 ms in, 120 ms out, 520 ms when it follows the establishing shot).
- **Per-screen motion (`src/ui/ui-motion.css`; `transform`, `opacity`, `clip-path`, `filter` and `stroke-dashoffset` only):** one authored moment — each sheet unfolds from its top fold (460 ms, a second sheet 70 ms later), then the current objective's route draws across the area map (900 ms from +360 ms) and its pin drops in (+1150 ms). The title draws its crest stroke by stroke and raises WILD / CROWN letter by letter; outcomes fade their wash and title in; the establishing shot slides its letterbox bars and title. No animation in this file loops (the loading scene's ambient atmosphere in `region-scenes.css` is separate) and none runs during gameplay; `.wc-ui--paused` holds every animation while the page is hidden.
- **Reduced motion:** `settings.reducedMotion` or the operating-system preference (`prefers-reduced-motion`, resolved in JS and exposed as `.wc-reduced-motion`) swaps screens instantly with a single-frame (16 ms) opacity cross-fade, shows sheets, the route and the title already drawn, renders dialogue as plain text, and gives controls authored static feedback instead (outline, inset ring, colour).

## Title, hero stage, map select, boss intro, and damage numbers

**Title.** The title card sits in the left third; the right two-thirds show the painted world map (`/ui/world-map-game.webp`), brighter (brightness .68) with a 46 s alternating push-in/pan (`wc-title-drift`, held still under reduced motion) and a golden firefly particle layer (`atmosphereMarkup('fireflies')` from `regionScenes.ts`, omitted under reduced motion). `TitleStage.ts` mounts a 3D diorama via `onTitleStageHost` and cross-fades it in only when the manifest has usable native assets; production assets are evidence-blocked, so production shows the painted backdrop.

**Hero stage.** `HeroPreview.ts` loads the selected native hero/weapon together with its own Tripo pedestal: Aren's weathered Warden stone, Yara's Heartroot roots, Vesper's rain-dark temple paving, or Sakda's sandstone courtyard. Candidate chapters and Trials fetch the preview-only `asset-source/playtests/hero-pedestals.json`; these evidence-blocked props never enter world catalogs or bypass the verified gate. `node scripts/assets/build-hero-pedestals.mjs` preserves native GLB/PBR data and measures a 2.25 m footprint plus the clear central standing surface before writing hashed manifests and provenance. The camera fits the real floor silhouette; the key light casts contact shadows. The former cylinder stack, blade cards, pebbles and glowing rings are removed. Hero and pedestal switch atomically, stale loads cannot replace the latest choice, and both are released on exit. Drag-to-turn, native skill showcases and reduced-motion behavior remain available.

**Map select.** `src/ui/worldMapSelect.ts`, `src/content/worldMapRegions.ts` and `map-select.css` build the illustrated map with SVG polygons traced over each painted land mass, a status pin per region (survey icons: pin = open, check = cleared, lock = locked/coming soon), a side panel and one Return to Title inside the panel. Hovering or focusing ANY region (locked included; buttons use `aria-disabled`, not `disabled`) lights that region — the others sink under a dark fill, the inspected one gets a light fill and glow — shows its name chip, and swaps the side panel to that region (chapter, status, thumbnail, tagline, encounters, Enter button `aria-disabled` when not playable). `bindWorldMapSelect(root, { panels: worldMapPanels(vm) })` does this locally (no dispatch, no re-render of unchanged regions).

**Boss intro.** `src/ui/BossIntro.ts` (styles in `boss-intro.css`) shows name + epithet in the lower third for 2.25 s when a boss reveal begins (see combat.md). Story bosses read `BOSS_TITLES` in `src/content/bossTitles.ts`; the trial boss stage derives its title with `bossTitleFromLabel(monsterName, stageTitle)`. The card is dismissed when the player leaves the game screen or the world is released.

**Damage numbers.** `DamageNumbers` consumes `damage` combat events (player and companion strikes alike, anchored at the target's position) and renders floating labels with tier classes: `--small` ≤6, `--heavy` ≥18, `--crit` ≥28. The 240 ms pop-in animates only the CSS `scale` property; the inline `transform` positions the label and the inline `opacity` fades it. Labels are hidden and parked off the overlay when the anchor projects outside NDC ±1.05 or behind the camera. Under reduced motion the pop-in and the rise are off. Star flash + shock ring come from `HitImpactFx`.

## Map intro, loading scene and establishing shot

After a hero is chosen in a local playtest the application shows `map-intro` (`mapIntroMarkup` for the selected map) and starts loading the region immediately. Continue, Skip, Enter, Space and Esc (gamepad A/B) all leave the intro; if the world is not ready the loading scene takes over, otherwise the world is revealed at once. While the intro is up no other screen may take over; a load failure replaces it with the loading error.

When the world is ready after an intro, the application calls `renderer.beginEstablishingShot({ seconds: 4, reducedMotion })`. While `establishingShotActive` the view model is `screen: 'game'` with `scene.establishingShot`, `canOpenWorldPanels` is false, the simulation stays paused at its first snapshot (the frame only advances idle animation, the camera sweep and rendering), gameplay input is disabled and the UI shows a letterboxed region title with a Skip hint. Esc, Enter, Space, a click or gamepad A/B/Start skip it (`skip-establishing-shot`); a pause, blur or panel also ends it at gameplay framing. When it ends the HUD fades in. Under reduced motion the renderer treats the shot as a no-op and play starts at once. Play Again, Try Again and retries load behind the plain loading scene without an intro or shot; the production campaign keeps its prologue dialogue and uses the loading scene (regions without authored scene art, such as Blood Bamboo Valley, use the Greenwake scene).

## Mana, skills and named stage monsters

The five passive keyboard skill cards show binding, mana cost, action label and authoritative reason. Funded, actionable skills use a filled jade/brass READY treatment; unavailable cards mute and explain Need N mana, Recovering, Release to strike, No target, Wait for windup, Paused, Traversing or Downed. They are not clickable action buttons. Heavy reflects its held charged requirement; Q reflects Root Tether versus Cleanse. Supported movement refills mana; the resource description does not promise regeneration while idle or blocked.

**Four heroes.** The hero-select roster lists Aren, Yara, Vesper and Sakda; the Stats tab reads “Ratings compare all heroes. The table lists live combat values.” The HUD controls hint takes the dodge wording from `HeroDefinition.dodgeLabel` (DIVE, PETAL STEP, MIST BLINK, GUARD DASH). Skill-card cost strings are derived from the shared constants (`PLAYER_SKILLS`, `SIGIL`): `12 / 20 MP` for Heavy, `15 / 35 MP` for the Sigil pair, other skills their own mana cost or FREE, and INSTINCT for the ultimate — shared by every hero, while labels come from the engine's per-hero snapshot labels. The ready ultimate glows per hero: storm teal for Aren, amber for Yara (`wc-ultimate-ready-heartroot`), violet with a crimson rim for Vesper (`wc-ultimate-ready-umbral`) and orange/gold for Sakda (`wc-ultimate-ready-ember`), selected by `.wc-hud[data-hero]`. Pause and outcome cards show the selected hero's crest and name for all four heroes.

**Attack cadence.** `HERO_COMBAT.attackPlaybackRate` gives Vesper a 1.35× offensive cadence and Sakda a 0.70× cadence relative to their previous timing; Aren and Yara stay at 1×. Their kit constants scale total durations, contact/release ticks, dash phases and chain windows together, rounded to 60 Hz simulation ticks. Vesper's live driver and hero-select showcase share `VesperAnimation.ts`: actual simulation duration drives playback, with a monotone piecewise map from rounded gameplay contacts to the native clip's contacts. This avoids a second speed-up in the preview and keeps Requiem's seventh gameplay slash at tick 91 on native tick 84, and its detonation at gameplay tick 122 on native tick 110. Sakda keeps its existing relative preview rate. Charge loops, hold thresholds, Cleanse, dodges, cooldowns, damage and status lifetimes retain their existing values. The opening Iai lasts 20 ticks and contacts at tick 7 (previously 27/9); Sakda's opening jab lasts 43 ticks and contacts at tick 16 (previously 30/11). Vesper's native GLB has been re-authored; the other heroes' GLBs are unchanged by this rework.

**Vesper spectral showcase.** `VesperShowcaseFx` reuses `StoryEffects` and `PoseAfterimages` on the real native actor and fitted katana; it does not invent targets or deal damage. Distinct sword-charge and shade-summoning stances lead into compressed windups, committed cuts and held recoveries. Black-violet wakes and dark frozen skeletal poses preserve the body silhouette, with thin crimson accents and a quiet interval before Requiem's final release. Replay, cancellation, hero switch and disposal clear the pools. Motion Blur off disables ghosts; Reduced Motion also disables the blade trail.

**Transparent-trail diagnosis.** The old blade shader wrote alpha 1 even where emission was nearly zero, producing black ribbon rectangles on the transparent showcase. Coverage now follows emission with premultiplied alpha. A real WebGL pixel probe changed the dark interior from RGBA `[1, 0, 7, 255]` to `[1, 0, 7, 7]`, with zero RGB differences against the old trail over an opaque world. Umbral ghosts alone use dark normal blending rather than HDR additive pink; the other heroes retain their materials. All six actual skill cards, covering fourteen native skill clips, were reviewed at CSS 1777×969 with the real katana. Evidence: `asset-source/playtests/evidence/combat-polish/vesper-reworked-skills-live.mp4` and `vesper-rework-live.json`.

The encounter panel lists current/next/cleared monsters, each skill roster and the current monster's HP bar (`value / max`). The world label above every on-screen hostile monster within 18 m shows that monster's HP too; defeated or neutral monsters lose their label. Within 1.5 m of a closed gate the panel reads "Sealed by <monster> — defeat the monster to open the gate". Generic bosses retain their ferocity/corruption meters and authored core indicators. Application-owned `MonsterLabels` projects a pooled set of labels from real native head/cast sockets, filters off-camera/far actors and clears on retirement. Neither labels nor cards invent simulation authority.

**Phase step (story bosses).** Below the phase title, Ferocity-driven story encounters show one instruction line from `encounterStatus.step` (absent for Trials, the Fall, the Hollow duel and the sequenced Koro/Asha fights, whose thorn and cub windows a generic line would misdescribe). `wear-down` asks for attacks that drain Ferocity; `tether` asks for the ability binding during a windup, names its mana price and that movement refills mana, then reads "Tethered" once it lands; `counter` asks for a perfect dodge then a strike; `cleanse` tells the player to strike until the corruption is exposed, then to Cleanse — it only reads "Cleansed" when the encounter resolves, never after a partial Cleanse. Keys come from the player's current bindings and prices from `PLAYER_SKILLS`. In candidate sessions above 760 px the centred boss panel sits below the status banner instead of under it.

**How-to-play cards.** `src/app/Tutorials.ts` schedules one card at a time, the first time its moment arrives: `controls` on the first gameplay frame; `cleanse-boss` when a story encounter that ends by cleansing begins (`encounterStatus.endsWithCleanse`; never for the subdue-only camp hunters); `tether`, `counter` and `cleanse` when a phase first asks for that action. While a card is open the simulation does not step, gameplay input is off, floating monster labels, damage numbers, target rings and the feedback layer (notices, companion warnings) are hidden, and Continue holds focus so Enter or the gamepad confirm button dismisses it. Dismissed cards are stored in `GameSettings.seenTutorials` (settings saved before this field load with an empty list); Settings → "How-to-play cards → Show again" clears it.

**Boss chip.** In a ramped trial the final stage of each map (Grove excluded) is a boss. The encounter panel shows a “Boss” chip (`.wc-boss-chip`) beside the current monster's name and gives its HP bar `data-boss="true"` for the larger bar, driven by `encounterStatus.trial.boss` or `monsters[].boss`. The pooled `MonsterLabels` world label shows the same chip (hidden for regular monsters) and sets `data-boss` on the label. Values come from the snapshot only; see the trial difficulty ramp in combat.md.

Below 760 px the HUD compacts for combat visibility: skill cards keep binding, cost and name while their status text stays only in the accessible name; the destination and party cards sit above the skill bar; the controls hint shrinks to fit. At 1440×900, 960×700 and 390×844 no HUD panels overlap and the document never scrolls horizontally.

The integrated native Greenwake HUD was exercised at actual CSS viewports 1024×768 and 1440×819, including zero mana, movement-earned readiness, named trial progression, real Defeat and Stage Complete. A controlled generic-boss view-model check at both widths observed no overlap between boss meters and the new encounter panel; it is component-layout evidence, not a native Asha scene or production asset qualification.
