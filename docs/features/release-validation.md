# Release validation and build artifacts

Normal development and CI builds remain usable while unfinished content is authored. `npm run build` proves TypeScript/Vite can emit a production bundle; it is not release acceptance and does not assert that character/prop GLBs, rig gates, references or benchmarks exist. The CI build artifact is a diagnostic build artifact, not a release-ready game.

## Commands

```sh
npm ci
npm run build
node --test tests/release/*.test.mjs
node scripts/release/validate.mjs --dist dist
node scripts/release/artifact.mjs --dist dist
```

The strict validator compares canonical asset-source/manifest.json with the normalized manifest emitted at dist/assets/manifest.json, including canonical kind/source type, hashes, content-addressed paths, applicable gates and ActionId mappings. For every native GLB it parses the real GLB v2 header/JSON/BIN structure, rejects external buffer/image URIs, requires sourceHash and outputHash to match emitted bytes, and binds the separate sourceInputHash to the approved reference hash. The preview must serve exact content-addressed bytes with GLB MIME and immutable caching. Composed Environment recipes have no GLB path/hash; their separately verified scene evidence binds current output hashes of every native component.

Verified native asset evidence must bind the asset ID, approved source-input hash, exact native GLB source/output hashes, per-check plugin producer rows, gates, and asset-specific negative controls. Character acceptance additionally requires measured G1/G3/G6/G10 producer output, exact G11 derivative-freeze parity, G12 native-skin joint correspondence where skinned, every required ActionId mapped directly to a named emitted GLTF animation, species-specific applicability evidence, and reviewed visual files bound to the current GLB output hash.
Static props may mark G1/G3 not applicable only when the GLB has no skin or animation and the evidence explains why; they must not invent bones. Static G6 requires asset.extras.wildCrownStaticVisibilityPolicy version 1 partitioning each renderable node into a required row with authored pixel/view thresholds or an explicit exclusion reason, plus rerendered hide-node negative controls for every required node. Static G10 measures each node's materials, vertex/index counts, finite positions and exact local/world bounds from native POSITION bytes, not accessor min/max alone. Every row references G10-static-bounds-corruption:<nodeIndex> and G10-wrong-culling-bounds:<nodeIndex>. The first control must reject mutated native POSITION through the normal measurement predicate; the second must measure the actual loaded mesh/frustum predicate changing from true baseline visibility to false corrupted visibility. Native buffers and cached box/sphere identities and values are restored in finally. Release validates per-primitive bounds/spheres, source transforms, camera matrices, corruption offsets, before/after counts and visibility, and exact nested/top-level control correspondence. Missing, malformed, duplicated, cross-node, stale-hash and no-op controls fail. G11 freeze/runtime parity and G12 no-skin applicability remain required. Unprofiled thresholds do not pass. Test-only GLBs are disposable contract probes, never production assets or quality acceptance.
Float32-equivalent decimal declarations are valid: comparison deltas subtract `Math.fround`-quantized operands while measured bounds remain unrounded. There is no universal absolute epsilon. At the native artifact-reader boundary, every POSITION accessor's finite, ordered declared bounds must match actual decoded values after the same quantization; evidence-declared bounds must also identify the exact current native JSON declaration. Changing source metadata and rebinding hashes cannot preserve stale good bounds evidence.
Native POSITION negative controls capture original bytes across all aliased ArrayBuffer/view addresses before mutating any view and restore each distinct address once. Static G10 rows require individual `primitiveDeclarations` binding node, mesh, primitive, POSITION accessor index and exact raw min/max from the native declaration. Aggregate node bounds remain checked but cannot substitute for these per-primitive provenance rows; stale equivalent metadata hidden by another primitive's union is rejected while freshly measured evidence for valid equivalent declarations remains eligible for review.
POSITION control validation derives expected after-counts and surviving local bounds from the physical mutation footprint of all native first-X writes. BufferView caching, byte offsets, component widths, interleaved strides and sparse accessor-private copies preserve the loader's aliasing rules. Shared overlapping views can corrupt later vertices in another primitive; they are not assumed to lose exactly one vertex each. Separate bufferViews over the same file bytes are independent loaded buffers. Exact measured counts/bounds remain required, and unchanged/non-detecting or forged disjoint evidence fails closed.
The native POSITION decoder admits at most 256MiB decoded working storage and 8M vertex occurrences (both exact limits are allowed). Admission happens before count-sized arrays or embedded-buffer decoding. Shared accessor/view storage is charged once; distinct views, sparse private storage, embedded buffers and converted strip/fan POSITION clones are charged independently. Repeated active mesh nodes charge occurrences, and inactive mesh declarations still charge once. This is a decoder budget, not a bound on total Node/browser/process memory. Explicit modes 4/5/6 are checked against actual GLTFLoader conversion/ownership, not triangle-only assumptions.

The full Asset Lab producer is shared by the browser and native integration probes. Static G6 aggregates by native node, emits node/mesh identity and eight named coverage rows, and requires hide controls only for authored required nodes. Excluded nodes still require both G10 controls. G1/G3/G6/G10/G11/G12 controls retain their own gate identity; an applicable non-detecting control fails rather than being renamed. Character G10 clip rows must exactly identify the measured native animation inventory, including required action clips; missing, duplicated and stale names are rejected as measurements, not mislabeled JSON errors.
Static G6 coverage must identify the producer's eight ordered views, and hide controls must retain all eight nonnegative integer pixel counts; zero-coverage views are measured data, not permission to omit a view. G10 culling receipts require arrays of exact native primitive rows rather than array-like JSON objects. A throwing POSITION measurement probe exercises byte restoration in `finally` without treating an exception as a detecting control.

Every native visual file must independently have status passed, current outputHash, a nonempty viewSet, a confined existing repository path and matching SHA-256. Aggregate visualEvidence also requires passed/current-output status. A stale or absent image cannot qualify through its retained view name.

G11 byte-copy parity is insufficient even when legacy evidence labels its gate passed. The current actual producer stays incomplete, reports its missingAcceptanceControls and has runtimeParity:null. Release requires the missing geometry/UV/material/frozen-live-scene measurements and their detecting mismatch controls before it can accept that gate; tooling does not manufacture a passed record. Exporter normalization now retains canonical gates/provider task provenance and recipe evidence, and verifies native/source-input hashes. Export success is not release acceptance: the real exporter-to-validator probe remains rejected at unmeasured G11.
Each claimed runtime-parity kind must supply canonical lowercase string SHA-256 values of exactly 64 characters for both live/frozen measurements and both before/after mismatch receipts. Before hashes must bind the reported row; after hashes must be present, well-formed and genuinely unequal. Missing, null, malformed, uppercase, trailing-line-terminator or coercible nonstring hashes cannot count as a detected mismatch; spelling differences are not byte mismatches.

Raw measurements marked measurement-complete-review-required do not qualify by themselves. Release requires independently reviewed gate values of passed, manifest evidenceStatus verified, and current-output visualEvidence status passed; tooling never promotes measurement status automatically.
The validator inventories emitted files and starts Vite's actual production preview. It checks root and deep-link HTML bytes/MIME/no-cache policy, resolves each entry module to a confined emitted file, fetches it and compares served bytes/MIME/cache, and verifies native GLB HTTP status, MIME, SHA-256 bytes and immutable content-addressed caching. It rejects symlink escapes, secret-bearing metadata, signed provider URLs and remote unchecked GLB dependencies. These are HTTP probes; no browser automation or deployment is started.


Release validation requires evidence/release/benchmarks.json to identify the exact current emitted-build inventory and measurement time, match reference-profile.json hardware/browser/viewport, include every route authored in BENCHMARK-ROUTES.md exactly once, and provide all required unit-tagged metrics. FPS, p95 and p99 checks use fixed limits from the reference profile; evidence cannot override them with self-selected profiles, limits or unrelated metrics. Missing routes, stale build identity, invalid units, missing evidence or missed limits fail. The artifact binds benchmark evidence bytes by path, size and SHA-256; tooling never invents benchmark results or thresholds.

The production build must emit dist/release-compatibility.json from actual authoritative exports, including integer buildSchema, integer saveSchema, and an authority identifier. The artifact generator inventories and hashes emitted dist files into dist/release-manifest.json and requires benchmark build identity to match; it does not independently grant release acceptance or copy template claims. Rollback metadata can be attached with --previous /path/to/prior/release-manifest.json; it records identity/compatibility only and always uses exercised: false.

The strict workflow is manually dispatched and does not deploy, create provider accounts, request Tripo tasks, or print credentials. It uploads the validated dist and bound release evidence. Ordinary CI builds/tests the validator and uploads a diagnostic artifact; passing it does not imply strict release acceptance. No production readiness is implied by build success or artifact-manifest generation.
