# Asset pipeline

The canonical production catalog is `asset-source/manifest.json`. `scripts/assets/export-runtime-manifest.mjs` validates it and emits the exact normalized top-level array at `public/assets/manifest.json`, fetched as `/assets/manifest.json`. Runtime kinds are character for actor-* native GLBs, prop for prop-* native GLBs, and environment for composed-recipe entries. The renderer consumes only explicit `runtimeUrl` values; it never guesses URLs or uses fallbacks. Native URL/hash fields remain null and evidence remains blocked in this canonical production catalog. `asset-source/playtests/*.json` is a separate development overlay and is never exported as production acceptance.

Canonical environmentRecipes declare sourceType: composed-recipe and intentionally omit kind; the exporter derives runtime kind: environment. Release validation compares native canonical kinds directly and requires the derived environment kind without duplicating it in source recipes.

sourceInputHash is the SHA-256 of the exact approved reference crop or upstream source image. sourceReference carries its path and context. sourceHash and outputHash are reserved for the exact native GLB source/derivative bytes; they remain null until a real file exists. For unchanged native exports sourceHash and outputHash are legitimately equal. The immutable runtime path is /assets/<assetId>/<outputHash>.glb, with nativeGlb=assets/<assetId>/<outputHash>.glb. The manifest can be revalidated/repointed to a later immutable revision. External buffer/image URIs are rejected; no sidecar dependencies or signed provider URLs.

EvidenceStatus uses the shared enum: not-started, in-progress, verified, blocked. verified means full applicable gates, raw plugin-row results, all negative controls, action coverage, species/geometry review, visual review, and frozen-output hash parity—not merely structural validation. Evidence files for eventual releases use evidence/assets/<assetId>.json, schemaVersion 1, exact assetId/sourceHash/outputHash, gates, per-check rows, negativeControls, and hashed review images. An unassigned asset-lab upload is a scratch measurement, never release evidence. Run node scripts/assets/test-runtime-manifest-guards.mjs to prove stale public catalogs and wrong native output hashes are rejected without touching production assets.
The exporter CLI identifies its entry point by canonical file identity, so paths containing spaces and symlinked temporary directories execute normally. Importing exportRuntimeManifest as a library does not run the CLI or rewrite a catalog. The guard script checks generated catalog semantics, symlink invocation and import inertness, not success-message wording.

## Regional environment composition and props

Every region uses an explicit composed recipe entry, not a GLB. Its exact componentAssetIds are distinct native prop-* GLBs. Trees, bamboo, rocks, bridges, cages, camps, shrines, gates, water systems, refuge shelters and ruins remain individual assets. Campaign REGION_PROP_PLACEMENTS owns exact placement order/transforms. ### Upstream lifecycle slots and authored walks

All 14 playtest monster GLBs (the eight Tripo quadrupeds, Howler, Rootling, Koro, Hornbill, Heron, Viper) carry two one-shot slots on top of the generic set (`creature-rig-kit.mjs` `MONSTER_SLOTS` / `SLOT_SECONDS` / `SLOT_LOOPS`, `MonsterAnimationProfiles.MONSTER_CLIP_ACTIONS`; 30 fps, rotation + Root/hip translation keys, byte-deterministic): `monster-death` 1.6 s (49 keys) and `monster-spawn` 1.4 s (43 keys). ## Measurement and acceptance

asset-lab.html loads an actual GLB through GLTFLoader and exports the source bytes unchanged, preserving native joints/inverse binds/clips. Temporary synthetic rigs may test measurement code only and are never Aren/Asha or production evidence. Evidence controls:

- Characters: G1 samples real bound properties for every clip at five or more times plus authored markers/transitions; a disconnected native track runs through the same sampler and must fail.
- Characters: G3 requires nonempty native skins/inverse binds, stop/reset/switch restore, local/world quaternion-equivalent comparisons and a deliberately unrestored-action control.
- Characters: G6 counts actual framebuffer pixels over eight views using explicit species/body-part mesh or bone-region annotations; hiding the real rendered region must reduce its pixels to zero. Missing authored policy stays incomplete.
- Static prop G6 reads GLTF asset.extras.wildCrownStaticVisibilityPolicy v1 with an exact required/excluded mesh-node partition and authored minimumVisiblePixels/minimumVisibleViews. It renders the actual loaded subject with source alpha/visibility/depth, measures the same eight views before/after hiding each required node, and fails closed without policy. G10-static records per-node finite positions, indices, materials and local/world bounds with a nonfinite-vertex corruption control. Static prop G1/G3/G12 are not-applicable only when the native GLB has no animations/skins; G11 byte freeze still applies. Test-only visible/hidden/alpha-zero/occluded/declared-exclusion GLBs are in /tmp/wc-static-prop-fixtures; they are not production assets or R05 vegetation qualification.
- G11 currently proves only byte-copy hash parity for the asset-lab export; it does not prove live runtime geometry/UV/material parity and stays incomplete until the frozen runtime scene is compared. G12 compares native skin joint indices to loaded skeleton correspondence; it remains incomplete until full rig-profile correspondence and wrong-LOD-bind controls are measured.
- Dynamic G10 records deformed bounds and contact-marker coverage from native clips, but planted-contact, mirrored-wrist, normalized-weight skin-topology and wrong-LOD-bind controls stay not-evaluated until authored effector/tolerance, handedness/pose, topology and bind-correspondence rules exist; a bounds delta alone does not establish failure. The culling control uses `THREE.Frustum.intersectsObject`, corrupt-weight detection uses `inspectSkinIntegrity`, and missing-contact detection uses `contactCoverage`. Missing target data keeps G10 incomplete.
- Static G10 emits exactly `G10-static-bounds-corruption:<nodeIndex>` and `G10-wrong-culling-bounds:<nodeIndex>` for every native mesh node, referenced by that row's `negativeControlIds`. The POSITION control mutates the first native vertex of each primitive, reruns the same geometry predicate, records actual before/after finite counts and bounds, and restores every unique buffer value in `finally` without changing attribute versions. Non-finite values must reduce the measured finite count and make the normal measurement incomplete; an integer/normalized buffer that cannot represent the mutation never reports detection. Bounds retain their measured precision rather than six-decimal rounding.
- Static wrong-culling controls recompute the loaded mesh's native sphere/bounds, frame a real frustum around it, and call `THREE.Frustum.intersectsObject(mesh)` before and after corrupting the geometry's cached sphere and box. Each primitive must transition from visible to rejected. Evidence includes native node/mesh/primitive identity, world/camera matrices, actual spheres/bounds and corruption offsets; detached box comparisons or unchanged visibility do not establish detection. Shared buffers and pre-existing box/sphere object identities and values are restored even on exceptions. Native scene/child order identifies instanced nodes because GLTFLoader may share association objects.
- The release validator decodes native POSITION values (including strided, normalized and sparse accessors), derives local/world bounds from those values, and verifies the exact per-node control payloads, primitive frustum/sphere geometry, nested/top-level controls and hashes. Missing, duplicated, cross-node, malformed, stale or no-op evidence fails closed. Producer status remains measurement-complete-review-required; this contract alignment does not grant production acceptance.
- Float32 bounds policy: measured and reported bounds retain their raw precision; cache/accessor comparisons and delta components are computed after `Math.fround` on each operand. A float32-equivalent decimal declaration therefore has zero comparison delta without any absolute epsilon. The release artifact reader independently compares each native accessor's finite, ordered min/max against its decoded POSITION values in this same space, then binds reported declared bounds to the exact current native JSON declaration. Stale good evidence cannot launder changed metadata, and a one-float32-step disagreement fails.
- Aliased native POSITION views are restored by backing ArrayBuffer and absolute byte address. Every targeted original byte is captured before any mutation, and each address is restored exactly once in finally; different subarray/interleaved view identities cannot capture an already-injected NaN as the original. Native source bytes, cache object identities/values and attribute versions remain unchanged. Each node also emits `primitiveDeclarations` with native node/mesh/primitive indices, POSITION accessor index and that primitive's exact raw declared local bounds. Release verifies each declaration independently, so another primitive's unchanged union extrema cannot hide stale equivalent metadata.
- Release validation models the actual POSITION fault footprint, not one lost vertex per primitive. It reconstructs GLTFLoader's shared bufferView storage, accessor offsets/strides and accessor-private sparse copies, applies all first-X native writes, then rereads every component of every affected vertex to derive exact finite/non-finite counts and surviving bounds. An overlapping view can lose additional later vertices; separate bufferViews of overlapping file ranges remain independent. The validator restores its temporary copies and still rejects no-op faults, invented disjoint counts and bounds containing corrupted vertices.
- POSITION resource admission is bounded before count-sized decoding: at most 268,435,456 bytes (256MiB) of decoded POSITION working storage and 8,000,000 vertex occurrences, inclusive. Storage charges Float64 decoded values once per accessor, loaded bytes once per distinct bufferView, accessor-private sparse values/indices, embedded-buffer decoded bytes and strip/fan conversion clones. Active native node instances each charge vertex occurrences; inactive mesh declarations charge once. These are decoder work budgets, not a whole-process memory claim: input GLB bytes, parsed JSON/base64 strings, Three.js scene objects, renderer allocations and release inventory are outside them. Base64 length admission does not decode another buffer.
- Explicit glTF modes 4/5/6 follow actual GLTFLoader ownership. Triangle mode retains shared accessor/view storage. Strip and fan conversion clone POSITION per primitive (including the interleaved slice) and produce triangle indices for indexed or nonindexed input. Validator faults mutate those private clones, not the source shared buffer. Bound accumulation reuses vector scratch storage rather than allocating a Vector3 per vertex.
- Static G6 inventory is one row per native mesh node, aggregating primitives and using native scene order for repeated mesh instances. Hide-control payloads include nodeIndex/nodeName/meshIndex; eight named renderedCoverage views retain measured zero pixels as well as positive coverage. Only required policy nodes need G6 hide controls; exclusions do not remove either G10 control. Top-level controls route to the actual G1/G3/G6/G10/G11/G12 gate, and inapplicable static G1/G3/G12 controls are omitted rather than aliased or marked passed.
- Release retains all eight producer view IDs in their measured order, including zero-coverage views, and requires eight integer pixel counts in each static G6 hide control. Complete static G10 cannot substitute for truncated/invented G6 views. Culling primitive receipts must be real arrays; array-like JSON objects are malformed evidence, not native producer output.

Retaining view names cannot make absent, stale, unreviewed, tampered or escaped files acceptable. Export preserves canonical gates, providerTaskId/provenance and recipe evidence; hashes remain bound to the approved source reference and exact native output.
- Canonical source provenance stays structured in asset-source/manifest.json; the exporter retains the existing public string pointer (asset-source/manifest.json#<assetId>) for native and recipe entries. ### Captured motion sources and method

Both clip sets are built offline from captured whole-body motion. Round 2's hand-keyed layers are gone: Sakda's two-bone IK limb layer with stance widening, Vesper's two-bone sword-arm solver with its per-frame Viterbi roll search and the fixed palm-tilt fist, and every pose-replacement key. The anatomy tests assert their absence (no `pose`, `body`, `torso`, `aim`, `sway` or `joints` field on any clip spec). What remains are bounded, measurable edits: source windows and time warps, mirroring, facing, in-place pinning, loop seams, cross-fades between whole captured segments, the soft joint guard and, for Vesper only, a katana wrist correction plus, on the clips listed below, a bounded shoulder correction.

**Vesper palm seat (re-authored).** The katana seat was previously computed on the back of the hand (fingers × thumb on a right hand), about 9.5 cm behind the armoured back plate, and every Vesper clip was tuned around that seat; the runtime fist therefore curled the fingers backwards. `handAnatomy` now mirrors the runtime rigid fist exactly: thumb from the lower-hand protrusion, palm normal thumb × fingers (hand-bone +X), seat at the hinge just outside the palm-side finger surface, rotated onto the captured shaft. The captured shaft (`bladeAxisHand`) and edge (`edgeAxisHand`) are unchanged; `palmHand` is the palm seat (the full-resolution runtime fit and the report agree within 2×10⁻⁶ rig units; the decimated in-game index seats it 2.7 mm away). The hand now holds the tsuka 0.29 m from the pommel (`KATANA_GRIP.gripFromPommel`), so the index side of the fist rested 1.5 cm behind the habaki (superseded by the fuchi seat below: 3.0 mm behind the tsuba); the handle band that `fitShaft` slims stays on the tsuka (`handleFromPommel` 0.20 m), so pommel, habaki and tsuba keep their native shape. Clearance now includes the tsuba as a 0.08 m disc (`guardClearance`, rim and half-radius rings on both faces), not only the steel line. With the hilt in the palm and the guard close to the fist, several captured poses press the fist, tsuka or guard into the thigh or torso. `armLayer` rotates only `mixamorig:RightArm` about the shoulder (forearm, hand and katana follow), searched per frame for the smallest rotation that clears the body capsules, the guard disc and the floor, smoothed, and still clamped by `limitJoints`; carried blades also keep a pitch ceiling so the low carry survives. Maximum shoulder corrections: walk 27.2°, run 23.1°, jump 20°, hit 14°, cheer 9.1°, defeat 19.5°, cleanse 34°, kunai fan 30°, shade swap 34°, Mist Blink 18.9°, air step 21.2°, Shadow Step 4°, and 12° frontal-arc turns at the Iai 3/4, Thousand Cuts and Requiem contacts. Thousand Cuts (tick 58), Requiem (tick 72) and Shadow Step (tick 8) bend the kissaki path onto the blade line around the thrust; Thousand Cuts' thrust source plays at 0.55 instead of 0.45 s/s to keep ≥ 3 m/s point speed. When the wrist correction cap binds, edge roll yields before the blade swing. Walk, run, jump, cheer, shade swap, Mist Blink and air step clear the body with the shoulder after the wrist has set the carry.

**Sources.** Per clip, in this order: (1) a Tripo `preset:biped:*` that Tripo retargeted onto the hero's own mixamo-spec rig (batches a–f for Sakda, a–g for Vesper above; no transfer error), (2) a Mixamo FBX retargeted through the world-space toolkit. Nothing falls back to hand-keyed poses. All 31 Mixamo files (12 Sakda in `asset-source/mixamo/sakda`, 19 Vesper in `asset-source/mixamo/vesper`) came through the official Mixamo UI in the user's signed-in account on Y Bot as FBX Binary (fbx7_2019), Without Skin, 30 fps, keyframe reduction none, default sliders, full clip, no mirror. `asset-source/mixamo/provenance.json` records catalogue id, display name, SHA-256 and bytes of each file. The licence allows royalty-free use in projects but not redistribution of the raw files: they stay in this private repository and never reach the GLB, a public bundle or a release; only the retargeted clips ship. In Place was requested for `run-with-sword` and six additional Vesper gait/sprint files. Measured on the delivered FBX files, Hips travel from first to last key is 0.000 m for all of them except `sprint.fbx`, which still travels 3.155 m in Y Bot metres (+2.682 m on Vesper's rig, 5.03 m/s) per 0.533 s cycle, so its entry records `inPlace: false`, `inPlaceRequested: true` and an explanatory note rather than the requested option.

**World-space FBX import** (`scripts/assets/mixamo-import.mjs`). `loadMixamoDonor` parses the FBX with three's `FBXLoader` and re-expresses it as an in-memory glTF source, so `Rig`, `buildClip` and `retargetFrames` treat a Mixamo donor exactly like a Tripo one. Bone names fold to `mixamorig:<Joint>`; centimetre files are converted to metres (detected from the rest Hips height); the rest pose comes from the bind pose for a skinned file and from the default node transforms for a Without Skin file. The donor is turned about +Y to the hero's rest heading (mean foot to toe direction; Y Bot faces +Z, the heroes +X; 90.75° for the Sakda files in the ledger), then `alignRestPose` takes each bone's minimal-arc rotation from the hero's rest bone direction to the donor's, so Mixamo's T-pose arms do not stack on the hero's A-pose (feet inherit the shin's alignment). `retargetFrames` then applies the world-space delta to each bone and scales Hips travel by the Hips-height ratio. `inPlace` pins Hips horizontal travel and keeps the vertical bob. Test contracts in `tests/rendering/mixamo-import.test.mjs`: names fold; the pin removes horizontal travel only; a Tripo FBX export of `front_kick_01` on Sakda's rig loads with the same rest positions, duration (2.5 s, 76 frames) and retargeted local rotations as the GLB of the same preset to under 0.5°; real Mixamo files give centimetre units, a 65-bone skeleton, 90° heading turn, a rest alignment above 20° on the arms, and every hero bone within 0.5° of the donor bone direction over every frame, for Sakda (roundhouse) and Vesper (outward slash).

**Mirroring.** `retargetFrames(…, mirror)` reflects the whole donor across the target's sagittal plane, inferred from the target's rest hip pair (horizontal Left→Right UpLeg direction): left/right partners swap, quaternion axes reflect as pseudovectors and Hips displacement reflects as a vector. The earlier version reflected x → −x, which is correct only for +Z-facing rigs; Vesper faces +X, so it reversed forward motion (measured: mirrored sprint stance toes slid forward while the chest heading stayed near 0, a moonwalk). After the fix the real sprint's stance toes push backward at −5.17 / −5.38 m/s mirrored against −5.44 / −5.20 m/s unmirrored (similar for fast-run and ninja-run), Hips travel keeps its direction (+2.682 → +2.683 m), and Vesper's lateral normal is 1.61° off +Z, so mirrored forward travel yaws 3.2°. Three unit regressions (+Z, +X and diagonal facing) pin forward travel, side swap and the unmoved opposite hand. Every mirrored conclusion measured before the fix is void; the left-handed throws were re-measured afterwards.

**Skin metric.** The deformation figures in this document are the p99.9, over every (edge, frame) sample of one clip, of |ln(deformed edge length / bind edge length)| for every unique triangle edge whose bind length is at least 3 mm (`skinDeformationReport`: CPU skinning at each keyframe). It is a log ratio, not a raw length ratio: 1.75485 means the p99.9 edge is stretched or squeezed by a factor of about e^1.75485 ≈ 5.8.

**Vesper coat-flap weight repair** (`scripts/assets/vesper-skin-weights.mjs`, `repairVesperFlapWeights(parsed)` → `{ glb, report }`). Cause of the one failing run candidate, measured before any change: the carried ninja-run's p99.9 was 2.06249 against the 1.75485 gate. Its worst frame (0.533 s) is a legal high-knee stride (right hip 94° from bind; native Tripo run 82°, the previous aren-run 57°, iai-1 37°), and none of the 74 worst edges crosses a dominant-bone boundary. They are the back coat flaps at belt height, where Tripo's auto-skin bleeds across limbs: 0.22–0.45 upper-arm weight over the whole back flank down to below the hip joint (10,790 right and 7,905 left vertices carry arm ≥ 0.3 more than 25 cm below the arm joint), thigh weight reaching 19 cm above the hip joint and co-weighted with the arm (16,884 / 5,550 vertices), and a hard four-influence slot flip at y ≈ 1.047 (endpoint weight difference 0.26 between neighbours 5–6 mm apart). Under that stride 5–6 mm flap edges stretched to 59–74 mm. The repair edits only copies of `JOINTS_0`/`WEIGHTS_0`: the arm rule fades upper-arm weight out below 1.20 m on vertices with no forearm/hand weight that are more than 0.10–0.16 m from the arm chain and already lower-torso weighted (hands it to Hips/Spine/Spine1/Spine2); the thigh rule fades thigh weight above 0.92–1.06 m and more than 0.12 m from the leg chain into Hips; three masked Laplacian passes smooth the edited vertices, then top-4 truncation and renormalisation. Positions, topology, textures, skeleton and inverse binds stay bit-identical and the rig file on disk is untouched. 104,402 of 975,606 vertices (10.7%) are edited; no sleeve or pauldron vertex with arm weight ≥ 0.5 changes by more than 0.02. Main's runtime measurement with the same geometry: ninja-run 2.06249 → 1.56895, the native Tripo run 1.66475 → 1.45416, iai-1 1.61418 → 1.38049; the strict 1.75485 skin gate, the body gate and the floor gate are unchanged. The manifest entry and provenance carry the repair report with `repairedBaseHash`; `sourceHash` stays the unrepaired rig file's hash.

Loop overlap is zero; clamping an overlap would freeze the end of this short cycle. In-place clips keep playback rate 1. For traveling clips, `AnimationController` caches authored planar speed after transforming Hips travel through the bind-parent-to-actor transform, including rotation and scale; the driver compares that speed with the motor rather than assuming the source's local Y is vertical. The gait author evaluates all indexed Foot/Toe-dominated skinned vertices at keys and eight subdivisions, then applies one constant Hips shift to place the minimum sole at actor Y = 1 mm. It does not use the bind-pose sole height, per-frame foot locking or body IK. Runtime gait evidence measures the actual controller, crossfades and engine motor; its planted-sole centroid includes foot roll and shows residual sliding, not a slip-free guarantee.
