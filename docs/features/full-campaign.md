# Full campaign, state and save API

## Authority and current status

`src/content/campaign.ts` and `src/content/story.ts` define the authored English campaign graph. The six-faction ending predicate, canonical fragments and obligations, checkpoint semantics, and campaign state remain owned by `packages/campaign`; runtime code does not define a second ending rule. Current campaign tests execute each leadership × Marek × Crown choice combination from an imported branch-entry checkpoint and continue through authored Crown/Orun events to an ending; they do not demonstrate the preceding full campaign routes or end-to-end objective reachability. A Chromium smoke exercised real IndexedDB slot persistence and import/error behavior. The game entry is not yet proven fully wired, Tripo GLBs are not proven loaded, and the 8–12 hour target has not been measured.

## World and content API

`src/game/contracts.ts` is the shared serializable type source. World positions are `{x,y,z}` in meters, Y-up. Region IDs are `greenwake`, `the-grove`, `whispering-canopy`, `blood-bamboo-valley`, `moonpine-ridge`, `mistveil-basin`, `sunmane-expanse`, `refuge`, and `heartroot-hollow`.

`REGIONS` provides bounds, nav nodes/ribbons, camera anchors, actor/interaction placements, per-region composed environment recipe IDs and explicit Tripo prop placements, encounter/asset IDs, reciprocal entrances/exits, traversal arcs, and common walk/collision data. `ACTORS` keeps stable ActorIds separate from exact manifest IDs (e.g. `actor-asha`); `ENVIRONMENT_RECIPES` are composed terrain/water/fog/collision recipes, not fictional GLBs. The Crowned Beast is Orun’s authored `actor-orun-crowned-beast` variant under the single `orun` identity. The council envoy is an antelope political delegate, not a combat companion. Physics and terrain presentation MUST consume the same `ground.surfaces` and `ground.colliders` arrays:

`src/content/levels/act-i.ts` and `later-acts.ts` export complete, explicitly authored `RegionDefinition` arrays: region-specific surfaces/colliders, navigation nodes/ribbons, camera anchors, entities, props, exits/traversal arcs, encounter participants, and restoration states. `RegionDefinition.movableObjects` describes authored movable prop instances separately from route geometry; Bamboo’s `camp-loose-snare` reuses the existing `prop-broken-snare` asset. `world.ts` keeps canonical `ACTORS`/`INTERACTIONS`, validates record identities and references, and derives reciprocal entrances, asset/prop indexes, and environment recipes whose IDs, prop placements, and surface IDs come from those records. `CampaignDirector` sets `refugeOpen` when the authorized Chapter 6 transition follows the required Fall of the Grove objectives; this opens Grove–Refuge travel during Chapter 6 even though Refuge content is assigned to Chapter 7, without changing chapter ownership. Safe-spawn selection prefers a valid authored incoming entrance and otherwise chooses an authored navigation root whose position lies on a walkable surface without overlapping a blocking collider. All nine current authored regions remain explicitly unaccepted; their presence in `REGIONS` is not evidence of content acceptance.

The Camp loose-snare action is separate from `camp-disable` and does not complete an encounter, quest, or objective. Koro’s utility Special (or, when Koro is absent from both party slots, Aren’s actual Staff Heavy/charged-Heavy hit on the focused prop) moves the authored `camp-loose-snare` over its 24 fixed simulation ticks only if the swept path and landing are supported and unoccupied. The engine emits one run-scoped `object-moved` event at landing; `CampaignDirector` validates its region, authored endpoints, prop identity, actor/interaction authorization, and facts before committing `objectMoved:camp-loose-snare` into campaign progress/checkpoints. Region load reconstructs the prop’s settled destination only from that committed fact. On storage failure the application keeps the exact event/idempotency key pending and fail-closes gameplay until retry succeeds; a reload before commit restores the last committed fact and source placement rather than treating staged simulation as durable progress.

- `GroundSurfaceDefinition`: `id`, profile (`plane`, `ramp`, `terrace`, `ridge`, `canopy`, `water`, `cavern`), explicit 3D `points`, `elevation`, optional `thickness`, `walkable`, `material`, `colliderId`, optional `traversalEvent`.
- `RegionColliderDefinition`: `id`, shape (`box`, `capsule`, `segment`), `from`, optional `to`/`radius`/`halfExtents`, `blocksMovement`, `blocksCamera`.
- Routes provide 3D endpoints and intermediate anchors, action/collider IDs and a semantic traversal event. Elevated surfaces are not implicitly reachable from touching an objective marker.

`QUESTS` declares the regional main quests, optional side quests, return beats, prologue and late-campaign milestones. Objectives require matching semantic events; touching a location alone does not complete one. `STORY_DIALOGUE` includes authored English connective and conditional presence/council beats; animals use short Echo Sense concepts rather than human speech. `CHAPTERS` defines eight chapters, progression, choices and absence-safe routes. `BRANCH_HISTORIES` describes the 18 pack-leadership × Marek-presence × Crown outcomes. Behavioral tests submit the corresponding Director choices and subsequent continuation events from branch-entry checkpoints; this is not evidence that all preceding routes are reachable end to end.

## Runtime API

`CampaignDirector` (`src/game/campaign/CampaignDirector.ts`) exposes:

- `startNewRun(runId?)` / `startShowcase(runId?)`
- `snapshot()` / `subscribe(listener)`
- `processEvent(WorldEvent)` and `choose(choiceId, optionId)` (Promises: durable run-ledger writes settle before returning)
- `selectParty(slot, companionId)`, `trackObjective(objectiveId|null)`, `travel(regionId, entranceId?)`
- `captureCheckpoint()`, `restoreCheckpoint(input)`, `ending()`
- `save`, `saveNewSlot`, `load`, `exportSave`, `importSave`

`WorldEvent` is discriminated and each event has `eventId` and `idempotencyKey`. The director only advances objectives when a matching semantic event is submitted; successful encounter events must match an authored encounter ID; rescue requires `safe:true`; fragment awards use the package helper; restoration is monotonic; chapter changes cannot skip a chapter or required main quest. Objective completion is runtime-derived, never a UI action. `evaluateEnding` from the domain package is the sole source for ending eligibility. Dominion history is kept separately from checkpoints and merged monotonically within a run. A replay run cannot be written to campaign slots or imported into a campaign.

The UI view model contract is derived from snapshot/runtime state. `GameViewModel.bindings` uses the explicit `InputBindingMaps` keyboard and gamepad records; remap actions identify the target device. Tracking is distinct from objective completion. Save-slot summaries and continue-slot ID must come from `SaveRepository.listSlots()`, not fabricated slot names.

## IndexedDB storage

`SaveRepository` opens `wild-crown-saves` IndexedDB schema 2 with `slots`, `runs`, and `settings` object stores; exported campaign envelopes remain format schema 1. Slot/checkpoint writes update the slot and same-run Dominion/event ledger in one read-write transaction. Settings and explicit keyboard/gamepad binding maps are stored together. The v1→v2 upgrade migrates the prior keyboard bindings and materializes the established pad defaults, honoring legacy `Gamepad Button N` overrides by moving that action to the gamepad map and removing its keyboard binding. Empty maps written under v2 remain intentionally empty.

Imports reject malformed, mismatched, replay and future-schema data before replacing local saves. Same-run imports merge Dominion history monotonically; loading an older same-run checkpoint restores its world checkpoint while retaining the local run-ledger history. New run IDs remain isolated. Quota and transaction failures surface explicit `SaveRepositoryError` codes; corrupt/future slots are left untouched, and `recovery()` exposes extant valid slot summaries, and `exportRawSlot()` can preserve a damaged slot record for recovery; ordinary `exportSlot()` validates it first.

Storage is browser IndexedDB; missing IndexedDB is an explicit error, never an in-memory fallback. Final-source Chromium verification used a real v1 database and confirmed the v2 settings migration, explicit keyboard/gamepad maps, and no refill of intentional empty maps. It also exercised settings round-trip; slot insert, close/reopen/load and export; valid, absent-progress, and malformed imports; old same-run checkpoint load/import with Dominion merge; future-schema recovery; aborted-transaction rollback; concurrent Director events; branch-local rewind with Dominion retention; event reapplication after rewind; and failed rescue-event rollback after a corrupted ledger. Quota exhaustion and a full campaign playthrough were not exercised. Root application wiring, production build, and full-playthrough verification remain integrator/release gates.
